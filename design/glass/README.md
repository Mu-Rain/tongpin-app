## 0. 一句话

保留品牌橙 `#FF6B4A`，把「浅灰底 `#F5F6F8` + 纯白卡片 + 24rpx 圆角」换成
**暖色渐变底 + 半透明玻璃卡片 + 更大圆角**。结构不动，只换视觉层。

## 1. 为什么选这套（而不是另两种）

| 方案 | 判断 | 理由 |
| --- | --- | --- |
| **暖光玻璃（本方案）** | ✅ 采用 | 品牌色可平移、亲和力强、与「找搭子」的温暖语义一致 |
| 新粗野主义 v2（`prototype/` 那套） | ✗ | 黑描边硬阴影记忆点强，但信息密度高、偏潮牌，新生场景偏冷硬 |
| 纯深色 Linear 风 | ✗ | 酷但亲和力弱，校园社交语境下容易显得像工具软件 |

## 4. 五条铁律（评审时可逐条打勾）

1. **一屏一个主卡。** 首页 =「今日同频」紫卡；大厅 =「发布需求」橙条；详情 =「我想搭」；我的 = 资料卡。主卡之外一律次级。
2. **颜色各有语义，不做装饰。** 橙=行动，紫=匹配/AI，绿=已认证/信誉正向，金=称号，红=危险/管理员。同一屏最多出现 3 种。
3. **玻璃守恒。** 每屏玻璃面积 ≤60%。以下三处**必须**不透明：主按钮、对方聊天气泡（本方案给了 86%，是上限）、输入框。
4. **数字等宽。** 信誉分、同频个数、倒计时、消息数用 `font-variant-numeric: tabular-nums`，读数不跳。
5. **降级要说人话。** 筛选退回更大范围时，浅黄提示条常驻（对应 `hall.vue` 的 `degradeTip`），不假装筛过。

## 5. 落地顺序建议（风险从低到高）

| 步 | 动作 | 影响面 | 可回滚 |
| --- | --- | --- | --- |
| 1 | 只换 `App.vue` 的 CSS 变量 + `page` 渐变底 | 全站，纯视觉 | 改回 10 行即可 |
| 2 | 抽一个 `.glass` 公共类，把各页 `.card` 指过去 | 全站 | 同上 |
| 3 | 逐页调间距/圆角/字号（首页 → 大厅 → 详情 → 我的） | 单页 | 单页回滚 |
| 4 | 首页加「今日同频」聚合卡 | 需读 `match_result` 的出参 | 先隐藏该卡即可 |
| 5 | 信誉分环形、搭子标签闪亮色 | 局部 | 局部 |

> 建议**先做 1–3**，这三步不碰任何 `.vue` 的 `<script>`，是最安全的一轮「换皮」。

## 6. 已知代价（提前说清）

- `backdrop-filter` 在 Android 10+ / iOS 9+ 可用；更低版本会退化成纯半透明。退化时把 `--tf-card` 调到 `rgba(255,255,255,.9)` 即可，一条变量解决。
- 渐变底 + 模糊对低端机有持续合成开销。实测思路：只在 `.page` 上铺渐变（一次绘制），玻璃卡数量控制在首屏 5 张以内——本方案六屏都在 5 张以内。
- `conic-gradient` 画信誉环在 App 端（webview）可用；若某端不支持，退回线性进度条。

## 8. 液态玻璃规格（v2，取代 v1 的磨砂玻璃）

### 8.1 五条规格逐条落地

| 规格 | 实现 | 代码位置 |
| --- | --- | --- |
| 大半径模糊 | `blur(26px)` | `--blur` 变量 |
| 饱和度拉高（避免发灰） | `saturate(1.9) brightness(1.04)` | 同上 |
| 10% 纯白底色 | `rgba(255,255,255,.10)` | `--glass` |
| 1px 高亮白边（物理厚度） | `border: 1px solid rgba(255,255,255,.85)` + 内阴影三道（上缘最亮/下缘稍暗/内发光） | `--glass-line` / `--glass-shadow` |
| 边缘折射变形 | SVG `feDisplacementMap` + SDF 法线位移图，只作用在边缘环内 | `buildLensFilter()` |

**关键判断：v1 的 `rgba(255,255,255,.58~.78)` 是「磨砂膜」，不是液态玻璃。**
它把背后内容洗白了，画面因此发灰。v2 只有 10% 白，靠 blur + saturate 把背后内容"透"上来 —— 这才是通透。

### 8.2 三个踩过的坑（别重复踩）

1. **`backdrop-filter` 不支持 `url()` 滤镜。** 想用 `backdrop-filter: url(#lensWarp)` 做折射行不通，Chrome 只接受 filter 函数。改用「复制背景层 + `filter: url(#lensWarp)` + 裁切」。
2. **`backdrop-filter` 与 `mask` 同用，遮罩会被忽略**（Chrome 已知缺陷）。所以遮罩要挂在外层的 `filter` 上，不能挂在 `backdrop-filter` 那层。
3. **大半径模糊会把折射抹平。** 这是物理矛盾。解法是分区：中心重度模糊、边缘锐利且折射（Apple 也是这么做的）。遮罩用「边缘环」切分两层。

### 8.3 底部导航的液体滑动

- 滑块是**凸出栏外**的独立玻璃胶囊（`-5px / 72px`，高于 62px 的底槽）
- 滑动曲线 `cubic-bezier(0.34, 1.56, 0.64, 1)` —— 到位时轻微过冲再收回，这是「液体」和「色块平移」的全部区别
- 按下时 `scale(1.05, 0.93)`，模拟被指腹压扁
- 位移量由 JS 实测 `--step`（相邻 tab 的 x 差），换屏宽不会错位

**结构上必须三层分离**（这是修掉「双层边」和「文字被盖」两个 bug 的关键）：

```html
<div class="tabbar-slot">          <!-- 定位 + 允许溢出 -->
  <div class="tabbar-tray"></div>  <!-- 底槽玻璃，柔边，z-0 -->
  <span class="lg-lens"></span>    <!-- 滑块玻璃，亮边，z-2 -->
  <div class="tabbar">…tabs…</div> <!-- 纯文字层，无背景，z-3 -->
</div>
```

> 文字必须单独成层：`.tabbar` 一旦带 `backdrop-filter` 就自成层叠上下文，
> 里面的 tab 再高的 z-index 也压不过外面的滑块。

### 8.4 动效清单

| 元素 | 动效 | 时长 / 曲线 |
| --- | --- | --- |
| 卡片入场 | `riseIn`：淡入 + 上移 14px + 缩放 0.994 | 620ms，逐项错峰 52ms |
| 首页主卡 | `breathe`：只改外发光，不动位移 | 7.5s 循环 |
| tab 滑块 | `translateX` 位移 | 520ms，回弹曲线 |
| tab 文字 | 颜色 + 字重过渡 | 320ms |
| 滑块按压 | `scale(1.05, 0.93)` | 140ms |

系统开启「减少动态效果」时全部退化为静态（`prefers-reduced-motion`）。

### 8.5 已知代价

- 折射依赖 JS 生成的位移图（384×384 PNG data URI），首帧多约 3ms。降级路径：`filter` 只保留 blur，视觉仍成立。
- 「复制背景」要求玻璃内部那份背景与屏幕背景**逐字相同**，所以背景收进 `--bg-main` 变量共享。改背景只改一处。
- 文字承载：10% 白底下正文会花，含长文本的玻璃卡额外叠 55% 白内衬（`background-color` 叠加，不改外缘透亮）。
