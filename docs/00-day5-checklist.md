## 1. 本次新增了什么

### 云函数（3 个，都要上传部署）

| 函数 | 干什么 |
|---|---|
| `message-send` | 发消息。落库 + 按 `clientMsgId` 去重 + 给对方未读 +1 + 更新会话摘要 |
| `message-list` | 拉消息。首次取最近 30 条，之后按 `created_at` 增量拉；**顺手把我自己的未读清 0** |
| `message-conversations` | 消息页的会话列表。带对方昵称/头像/学校、最后一条、未读数、搭子标签与颜色 |

### 页面（2 个）

| 页面 | 位置 |
|---|---|
| `pages/messages/messages.vue` | 消息列表。顶部 AI 机器人入口 → 会话卡片流（带未读红点）→ 底部「我的搭子与标签 →」 |
| `pages/chat/chat.vue` | 聊天。顶部对方信息条（含搭子标签 + 连接状态）→ 消息气泡 → 底部「🖼 + 输入框 + 发送」 |

### 公共模块

- `dazi-app/app/common/chat/transport.js` —— **聊天传输层**。7 个接口：`start / stop / send / fetchSince / touch / onMessages / onStatus / onError`。
  页面**只准调这 7 个**，绝不许自己在页面里写 `setInterval` 轮询。将来换 WebSocket 时只改这一个文件（见 [06-chat-transport.md](./06-chat-transport.md)）。

## 2. 你要点的（照着做）

### 第 1 步 · 上传部署 3 个云函数

在 HBuilderX 里，`uniCloud-alipay/cloudfunctions/` 下逐个右键：

1. `message-send` → **上传部署**
2. `message-list` → **上传部署**
3. `message-conversations` → **上传部署**

> ⚠️ 别点「运行-云函数测试」，那个会去找 `*.test.js`，我们没写，必然失败。

### 第 2 步 · 重新运行到手机

改了 `pages.json`（新增 2 个页面），**必须重新编译**。

- 菜单「运行 → 运行到手机或模拟器 → 运行到 Android App 基座」
- 或者直接热重载

### 第 3 步 · 建 conversations 集合的索引（重要，不然会慢）

登录 [uniCloud 控制台](https://unicloud.dcloud.net.cn/) → 选 `tongpin-dev` → 云数据库 → `messages` 集合 → 索引管理，加一个：

| 字段 | 类型 | 说明 |
|---|---|---|
| `conversation_id` | 升序 | 复合索引的左边 |
| `created_at` | 升序 | 右边 |

**为什么要加**：`message-list` 每 3 秒查一次「某会话里比某时刻新的消息」，没索引就得全表扫，几十条消息就开始卡。

> 注意：**集合是第一次写入时自动建的**。如果 `messages` 还没出现，先发一条消息再看。

### 第 4 步 · 双账号验收（必须两个账号）

1. 用 **A 账号**登录 → 发一条搭子卡片
2. 用 **B 账号**登录 → 申请 → 切回 A → 同意
3. A 的首页点「消息」→ 应该看到 B 的会话卡片（**有未读红点**）
4. 点进去 → 发一条「你好」
5. **切到 B 账号** → 消息页看到红点 → 点进去能看到「你好」
6. B 回一条 → 切回 A，**等 3 秒**（不要退出重进），A 的聊天页应该自己冒出新气泡

第 6 步是这一天的核心验收点 —— **不退出页面、不手动刷新，消息自己出现**。

### 第 5 步 · 顺便验三件小事

| 验什么 | 预期 |
|---|---|
| 顶部状态 | 显示「已连接」；拔网线/关 WiFi 会变「重连中」 |
| 图片消息 | 点输入框左边的 🖼 → 选图 → 上传后自己发出去 |
| 断线补拉 | 手机开飞行模式 → 发一条（会显示"发送失败，点此重试"）→ 关飞行模式 → 点重试 → 成功，且**不会变成两条** |

## 3. 点「发送」时后台发生的事

1. 页面先本地插一条气泡（乐观更新），所以你按下按钮的瞬间消息就出现了
2. `message-send` 校验：token → 会话成员 → `type` 合法 → 内容非空且 ≤500 字
3. **按 `client_msg_id` 判重**：如果这个 id 已经存在，直接返回老那条，不重复写入
   → 这就是"重试发送不会变两条"的原因
4. 写入 `messages`，`created_at` 用**服务端时间**（不信客户端时钟）
5. 给会话里**除我以外**的成员 `unread_count + 1`；我自己的那行清 0 并把 `last_read` 推到这条
6. 更新 `conversations` 的 `last_message_text` / `last_message_at`（消息页列表要显示）
7. 写一条 `notifications`（`try/catch` 包住 —— 通知失败不该让发消息失败）

**对方怎么收到**：聊天页每 3 秒问一次 `message-list`，拿到比自己记录的 `lastMessageId` 更新的消息就追加。

> 这是 MVP 的轮询方案，延迟 1.5–3 秒。真要做到"秒回"要换 WebSocket，接口已经留好（`transport.js`），
> **见 [06-chat-transport.md](./06-chat-transport.md)**。免费额度算下来够用：聊天页开着 1 小时约 1200 次调用，
> 支付宝云免费版 1.5 万次/月，按每天聊 2 小时算能用约 12 天/月 —— 所以静默 3 分钟后会自动降到 10 秒一次。

## 4. 在控制台核对数据

发完一条消息后，去 `tongpin-dev` → 云数据库看：

| 集合 | 应该看到 |
|---|---|
| `messages` | 新的一行：`conversation_id` / `sender_id` / `type` / `content` / `client_msg_id` / `created_at` |
| `conversation_members` | 两行（你和对方），其中**对方那行 `unread_count` 是 1**，你的是 0 |
| `conversations` | `last_message_text` 是刚发的那句，`last_message_at` 是刚才的时间戳 |
| `notifications` | 一行新通知 |

## 5. 报错对照表

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 消息页空着，一直转圈 | 云函数没部署 | 3 个函数都「上传部署」 |
| 提示「未登录」/「登录已过期」 | token 没传或已过期 | 退出重登一次；若还报，检查 `transport.js` 是否把 token 放进了 data |
| 提示「你不在这个会话里」 | 会话成员表没写进去 | 检查 `card-apply` 的 accept 是否建了 `conversation_members`（第 4 天做的） |
| 消息发出去但对方看不到 | 对方没在聊天页/轮询没跑 | 让对方真的**停留在聊天页**上（退到后台会 stop 轮询） |
| 发出去了但显示"发送失败" | `code !== 0` 被当成失败，或者真的网络断了 | 看 HBuilderX 控制台里云函数的返回 |
| 自己发的消息变成两条 | 去重没生效 | 检查 `client_msg_id` 是否两边都传了（页面 → transport → 云函数） |
| 聊天页一进去就报错 | `conversationId` 没传到 | 从消息页点进聊天页，别直接输入 URL |
| 顶部一直显示「重连中」 | 请求失败在退避 | 看控制台报错；退避是 3s→6s→12s→24s→最多 30s |
| 图片上传失败 | 云存储没开或路径不对 | 支付宝云免费版送 5GB 云存储；检查 `chat/` 路径权限 |
| 改了代码手机上没变化 | 没重新编译 | 改了 `pages.json` 或新增文件必须重新运行 |

## 7. 已知取舍（写下来，别当成 bug）

| 取舍 | 说明 |
|---|---|
| **轮询不是推送** | 延迟 1.5–3 秒；锁屏/退到后台收不到（`onHide` 会 stop）。真推送要接 uni-push，排在 M3 |
| **聊天页不在 tabBar 里** | 它从消息页 `navigateTo` 进去，是二级页 |
| **AI 情绪机器人是占位** | 点进去只有一句说明。真正的情绪引导对话排在第 6 天之后 |
| **消息没有分页历史** | 首次只拉最近 30 条，没有"上拉看更早"（轮询版够用，换 WebSocket 时一起做） |
| **没有撤回/已读回执** | 不在 MVP 范围 |
| **未读数用冗余字段** | 存在 `conversation_members.unread_count`，不去 `count` 消息表（几十个会话时 `count` 会卡）|
