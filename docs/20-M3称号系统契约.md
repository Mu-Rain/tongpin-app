## 0. 本轮做什么 / 不做什么

| 做 | 不做（推迟） |
|---|---|
| `titles` / `user_titles` 两张集合 + DDL | 9 个稀有称号的内容与条件 |
| **3 个易得称号**（完善资料 / 通过认证 / 首次搭成） | 后台称号配置页（M4 B6） |

## 1. 可升级性（照抄信誉系统的做法）

`titles` 是数据表，代码里只是**兜底默认值**。云函数按 `code` 查表；**表不存在 / 该 code 不存在 / active=false** 三种情况一律回落到内置表。

内置 3 条（也是将来往表里插数据的模板）：

| code | name | rarity | condition_type | condition_text | 判定依据 |
|---|---|---|---|---|---|
| `profile_complete` | 资料完整 | common | `profile` | 填了昵称、头像、学校，并选了至少 1 个标签 | 见 §3.1 判定 |
| `verify_pass` | 学生已认证 | common | `verify` | 通过一次学生认证 | `is_verified === true` 或 `verify_status === 'approved'` 或 `schoolVerified === true` |
| `first_buddy` | 第一次搭成 | common | `buddy` | 和同学完整搭成一次（双方都确认） | 有 `credit_events` 的 `buddy_done` 流水；该表读不到时回落 `buddy_relations.done_count >= 1` |

**关键决定**：`user_titles.title_id` 里存的是 **code 字符串**（`profile_complete`），不是 `titles._id`。
理由：`titles` 表本轮可以是空的（用户不必去后台插数据），存 code 才能在「表空」的情况下照常工作；将来后台改了名字/文案，已获得的记录不用迁移。

## 2. 集合与索引

```
titles
  _id, code(string, 唯一), name, desc, rarity('common'|'rare'|'epic'),
  condition_type, condition_value(可为空), condition_text, active(bool), sort(int), created_at(long)

user_titles
  _id, user_id, title_id(string = titles.code), obtained_at(long), is_equipped(bool)
```

索引：
- `titles`：`code` 升序，**唯一**
- `user_titles`：`(user_id, title_id)` **唯一**（防重复发）、`user_id` 升序

`uni-id-users` 已有 `current_title_id`（见 `docs/03-database.md:279`），本轮开始真正用它，存 code。

## 3. 云函数

### 3.1 `title-list`（新建，任何登录用户）

入参：`{ token }`

出参：
```json
{ "code": 0, "data": {
  "list": [{ "code": "profile_complete", "name": "资料完整", "desc": "", "rarity": "common",
             "obtained": true, "is_equipped": true, "obtained_at": 1760000000000,
             "condition_text": "填了昵称、头像、学校，并选了至少 1 个标签", "sort": 10 }],
  "equipped": { "code": "profile_complete", "name": "资料完整" },
  "newly":    [{ "code": "first_buddy", "name": "第一次搭成" }],
  "total": 3
} }
```

**行为顺序（重要）**：
1. **先评估补发**：对内置 3 条（以及 `titles` 表里 `active=true` 的其它项）逐条判定条件，满足且 `user_titles` 里还没有 → 插一条 `is_equipped:false`，并记入 `newly`。**必须幂等**：已有记录就跳过，不许重复插、不许把 `obtained_at` 覆盖。
2. 再拼全量 `list`（表里的项 + 内置项，按 `sort` 升序），`obtained` 与 `is_equipped` 从 `user_titles` 读。
3. `equipped` 取 `is_equipped === true` 的那一条，没有就是 `null`。
4. `newly` 只包含**本次调用新发**的，前端据此弹一次提示。**重复进页面不重复弹。**

判定的读法（拿不到当不满足，绝不报错）：
- `profile_complete`：`uni-id-users` 里该用户 `nickname` 非空 **且**（`avatar` 或 `avatar_url`）非空 **且**（`school` 或 `school_name` 或 `school_id`）非空 **且** `user_tags` 至少 1 条。
- `verify_pass`：`is_verified === true` 或 `verify_status === 'approved'` 或 `schoolVerified === true`，三者任一。
- `first_buddy`：见 §1 表格；`credit_events` 查询失败（表不存在）时**必须**回落 `buddy_relations` 的 `done_count >= 1`，不许直接判 false。

**降级**：两张新表都不存在时，接口仍然返 200，`list` 用内置 3 条、`obtained` 全 false、`newly` 为空（因为没有地方记「已获得」）。**不许 500。**

### 3.2 `title-equip`（新建，任何登录用户）

入参：`{ token, code }`（`code === ''` 表示摘掉当前佩戴）

出参：`{ code: 0, data: { equipped: { code, name } | null } }`

规则：
- `code` 必须已获得（`user_titles` 里有 `user_id + title_id=code`），否则 **404**；`titles` 表里没有但属内置 3 条的 code，视为合法。
- 切换：**先**把该用户所有 `is_equipped:true` 的记录置 false，**再**把目标那条置 true；同时写 `uni-id-users.current_title_id = code`。摘掉时只做第一步，`current_title_id` 写 `''`。
- 不改 `obtained_at`，不删记录。
- 并发/重复点击结果一致（幂等）。

### 3.3 `user-profile`（改造：只加字段，不动既有结构）

在 `PUBLIC_FIELDS` 白名单里加 `current_title_id: true`（**白名单漏字段是本项目踩过的坑**），并在出参**顶层**新增：

```json
"current_title": { "code": "profile_complete", "name": "资料完整" }
```

- 名字解析顺序：`titles` 表按 code 查 → 查不到用内置 3 条 → 都没有就 `null`。
- 没佩戴时 `current_title` 为 `null`。
- **除这一项外，出参其余字段、顺序、含义一律不许改**（前端 chat.vue / user.vue 都在读它）。

## 4. 前端

- 新建 `app/pages/title/title.vue`：称号墙。已获得的高亮、未获得的置灰并显示 `condition_text`；点已获得的（且当前未佩戴）调 `title-equip`；当前佩戴那条显示「佩戴中」并给「摘下」。
- `app/pages.json` 追加 `pages/title/title`（第 26 条路由，紧跟 `pages/credit/credit`；tabBar 4 项不许动）。
- `app/pages/mine/mine.vue`：资料卡里加「称号墙」入口（与信誉分同一行的风格），并显示**当前佩戴称号**（没有就不显示）；进页面时调一次 `title-list`，`newly` 非空则 `uni.showToast` 弹一次（本次会话内同一 code 不重复弹）。
- `app/pages/user/user.vue`（**对方主页**）：资料卡显示对方 `current_title`（没有就不显示），不显示「佩戴中」等管理态文案。
- `title-list` 不存在或报错时：称号墙显示空态 +「稍后再试」，**不许白屏、不许卡 loading**。

## 5. 铁律（违反即白屏或线上事故）

1. `.vue` 模板里**不许**直接用 `<script>` 顶层 `const`（须先在 `data()` 注册）——踩过白屏。
2. 业务错误走 `code`，不 `throw`。
3. 云函数目录**自包含**：每个函数只有 `index.js` + `package.json`，不许 `require` 目录外的东西；共用逻辑就内联复制（以 `title-list` 那份为准）。
4. 表不存在时静默降级；但**拿不到当前用户必须 500**（token 无效）。
5. 改完 `.js` 与抽出来的 `<script>` 段都要 `node --check`。
6. 注释只写「为什么」，全中文。老数据缺字段一律 `pickInt` / `!!` 兜底。
