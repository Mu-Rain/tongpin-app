### 1.1 进入会话的时序（实测调用链）

        → 命中即先渲染（loading=false），不等网络

### 1.2 本地层结论
- **没有 SQLite**：全工程 grep `plus.sqlite|openDatabase|SQLite` = **0 命中**（`dazi-app/app` 下 .vue/.js/.json）。
- 有的是 **storage 快照 + 内存合并**：`chat.vue` 快照键 `chat_snap_v1_<uid>_<conversationId>`（40 条、100KB 上限、800ms debounce，`onHide`/`onUnload` flush）；`messages.vue` 快照键 `conv_snap_v1_<uid>`（40 条、60KB，剥掉所有 http 链接）。
- 快照的取舍（已写在代码注释）：临时链接不进快照（会过期），所以秒开瞬间头像/图片可能先显示默认图。

### 1.3 首屏是否被云端阻塞
- **首次进入（无快照）**：`loading` 为真直到首个 `message-list` 返回 → 受云函数冷启动支配（结构性证据：1 次 callFunction + 云函数内 `token` 查询 + 会话成员查询 + 消息查询，见 `message-list/index.js:72`、`:144`、`:198`）。
- **有快照**：`restoreSnapshot()` 同步渲染，云端结果回来只做增量合并 → 首屏不等网络。
- 离线：有快照可读历史；无快照时 `onLoaded` 在失败时也会放开 loading（`transport.js:199-205`），显示空态而不是无限转圈。

## 3. 图片下载与渲染链路

### 3.1 换链接（getTempFileURL）的命中顺序

```
resolveFileURLs()            chat.vue:2126
  for 每条 image 消息（content 是 cloud:// 且 !resolved）
    1) getLocalImage(fileID)  → 命中本地已存文件：displayUrl = file://，零流量  imageFile.js:77

```

证据：`chat.vue:2133-2158`（命中顺序）、`:2160-2212`（批量换链 + 回填 + 落盘）、`common/chat/imageCache.js:16-20`（键 `chat_img_url_cache`、TTL 100 分钟、最多 300 条）、`common/chat/imageFile.js:18-22`（键 `chat_img_file_cache`、`MAX_FILES = 120`、`MAX_CONCURRENT = 3`）、`:114-122`（`downloadFile` → `saveFile`）。

### 3.2 渲染侧
- 模板：`chat.vue:187-204` 两段式 —— 不可见探针（`.bubble-probe`，`mode="widthFix"`）先量原始宽高，再渲染 `mode="aspectFit"` + 内联 `width/height`（由 `setImgBox` 按原图比例算）的真图；`@error` 兜底。
- **没有 lazy-load**：`chat.vue` 中 `lazy-load` 命中 **0** 次（其它 7 个页面有：buddy/favorites/feed/friend/hall/index/messages）。
- **没有虚拟列表**：`chat.vue:107` `<view v-for="m in messages" :key="m.key" ...>` 全量渲染；分页只是**减少单次网络量**，DOM 随上拉不断累积（`loadOlder` 前插，`:1318` 附近）。
- 失败与占位：`onImgError` 会清 `displayUrl` + 失效 URL 缓存（`invalidateImageUrl`），模板回落「图片加载失败 / 图片加载中…」灰块（`:205-207`）。

### 3.3 CDN 与链接寿命
- 链接来自 `uniCloud.getTempFileURL`（`chat.vue:2160+`、各云函数内同名调用），域名由云厂商分配；**代码侧无自定义 CDN 域名**（全工程 `CDN` 仅 3 处注释性提及，无实际域名）。
- 链接寿命：代码按「约 2 小时」处理（`imageCache.js:12` 注释、TTL 取 100 分钟）。过期后：`<image>` 报错 → `onImgError` 删缓存 → 下次进入重新换链。

## 5. 根因判断（按收益排序）

1. **显示侧不分场景**：聊天里显示的就是 1280 宽的上传图（一张大图在弱网下几百 KB），而气泡宽度只有 ~380rpx。缺缩略图 → 首屏图片流量与解码耗时都偏高。
2. **链接必须每 100 分钟换一次**：`getTempFileURL` 是一次云函数外网往返（批量后 1 次/屏），叠加冷启动可能几百毫秒；这是「隔一天再进会话，图片要等」的直接原因（URL 缓存过期、文件缓存若被 120 条上限淘汰也失效）。
3. **首屏与云端耦合（首次进入）**：无快照时 `loading` 等 1 个 `message-list` RTT；有快照时不阻塞。**这条已在上一轮解决**，剩下的是「快照还没有时的冷进入」。
4. **DOM 不裁剪**：长会话翻十几页后 `messages` 数组持续增长，`scroll-view` 内节点线性增加 → 滚动掉帧。
5. **启动必过登录页**：见第 6 节，独立问题。

## 6. 附加问题：杀后台重进时登录页闪现 0.x 秒

```
冷启动（entryPage = pages/splash/splash，pages.json:4）
  App.vue:6 onLaunch → this.tryAutoLogin()   ← 异步，不 await
        └ 内部 await uniCloud.callFunction('user-auto-login')   App.vue:112
             成功才写 autoLogin = { state:'ok' }              App.vue:122
  splash.vue:25-29  固定 1800ms 后无条件 uni.reLaunch('/pages/login/login')
  login.vue:134-141  onShow 读两次：0ms 和 300ms
  login.vue:201-212  readAutoLogin() 只有 info && auto.state==='ok' 才 reLaunch('/pages/index/index')
```

**根因**：启动页**不等待**登录态，且登录页的判定依赖一个**异步云函数回包**。当页面 1.8 秒到时 `autoLogin.state` 还不是 `'ok'`（云函数冷启动 > 1.8s、或上一次是表单登录写入的是 `ok` 但本次启动 `user-auto-login` 尚未回包、或回包失败走了 `catch` 分支写 `'none'`），登录页先渲染；随后 300ms 那次重读命中 `ok` → 跳首页 → 用户看到登录页闪一下。

补充证据：`login.vue:325`、`register.vue:214` 会在表单登录/注册成功后写 `state:'ok'`；`index.vue:848-850` 退出登录时 `removeStorageSync('autoLogin')`。

### 建议修法（第二阶段，两选一或叠加）
- **A（推荐）**：`splash.vue` 不再固定 1.8s 跳登录页，改成「轮询 `autoLogin.state`（最长 ~1.5s，50ms 一次）：`ok` → `/pages/index/index`；`fail`/超时 → `/pages/login/login`」。改动只在 `splash.vue`，可回滚。
- **B**：`login.vue` 首帧渲染前先同步判定一次（`token` + `userInfo` 存在即视为可能已登录），命中则显示启动图占位而不是登录表单，等 `ok` 再跳。
