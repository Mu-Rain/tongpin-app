## 0. 产品决定（用户已拍板，不要再改）

| 编号 | 决定 | 理由 |
|---|---|---|
| D1 | **删除好友后仍可聊天**（临时会话）。聊天页顶部常驻提示条「你们已不是好友」+ 两个按钮「加入黑名单」「加为好友」 | 禁发会让用户以为坏了；不禁又等于删好友没效果。QQ 的做法 |
| D2 | **黑名单是单向彻底静默**：他发的我一条都收不到、会话从我的消息页消失、他也加不了我好友、我也不能给他发 | 用户点拉黑就是不想再看到这个人 |
| D3 | **有搭子关系的会话强制置顶且不可取消**（用户原话：「不能调成不置顶」） | 搭子是本产品的核心关系 |
| D4 | 撤回窗口 **2 分钟** | 微信/QQ 同量级 |
| D5 | 清空聊天记录**只清我这一侧**，不影响对方 | 不影响他人数据 |

### 2.1 `conversation_members` 新增 4 个字段

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `pinned` | bool | `false` | **我这一侧**的置顶。搭子会话不看这个值（强制置顶） |

## 3. 新云函数契约（6 个）

所有云函数统一：`exports.main = async (event) => {}`，**业务错误一律 `return { code, msg }`，不 throw**（内部 `fail()` 抛错必须在 `exports.main` 末尾 try/catch 转成 `{code,msg}`，与现有 39 个云函数一致）。

### 3.1 `user-block`

```
入参 { token, action: 'add' | 'remove' | 'list' | 'status', target_user_id?, target_user_ids? }
```

| action | 入参 | 出参 data |
|---|---|---|
| `add` | `target_user_id` | `{ blocked: true }` |
| `remove` | `target_user_id` | `{ blocked: false }` |
| `list` | 无 | `{ list: [{ user_id, nickname, avatar, created_at }], total }`，上限 100 |
| `status` | `target_user_ids`（数组，≤50） | `{ map: { [targetId]: true } }` —— 只放**我拉黑过**的人 |

规则：
- `add` 幂等（已存在直接返回 `blocked:true`）；不能拉黑自己 → `code:400`「不能拉黑自己」
- `add` 成功后顺手：把我和他之间的 `friendships` 删掉、`friend_requests` 里 pending 的置 `canceled`
- `remove` 幂等
- `status` 查询失败降级返回 `{ map: {} }` 不报错

### 3.2 `message-recall`

```
入参 { token, message_id }
出参 { code:0, msg:'ok', data:{ message_id, recalled:true, recalled_at } }
```

- 只能撤回**自己发的**：`sender_id !== me._id` → `code:403`「只能撤回自己的消息」
- 超过 `RECALL_WINDOW_MS = 120000`（2 分钟）→ `code:400`「超过 2 分钟，不能撤回了」
- 已撤回再调 → `code:0` 幂等返回
- 消息不存在 → `code:404`「消息不存在」
- 必须是会话成员
- 撤回后把 `conversations.last_message_text` 若指向这条则改成 `'[消息已撤回]'`

### 3.3 `message-clear`

```
入参 { token, conversation_id }
出参 { code:0, msg:'ok', data:{ conversation_id, cleared_at } }
```

- 把 `conversation_members` 里**我这一行**的 `cleared_at` 设为 `Date.now()`，`unread_count` 置 0
- 不删任何消息，不动对方那一行
- 不是成员 → `code:403`

### 3.4 `conversation-setting`

```
入参 { token, conversation_id, action: 'pin' | 'unpin' | 'mute' | 'unmute' }
出参 { code:0, msg:'ok', data:{ conversation_id, pinned, muted, pin_locked } }
```

- `pin_locked` = 我和对方之间是否存在 `buddy_relations.status === 'active'` 的关系。为 `true` 时：
  - `unpin` **不报错**，但 `pinned` 仍返回 `true`、`pin_locked` 仍 `true`（前端据此提示「有搭子关系的会话会一直置顶」）
  - 存库时也把 `pinned` 写成 `true`
- `mute` / `unmute` 不受 `pin_locked` 影响
- 不是成员 → `code:403`

### 3.5 `report-submit`

```
入参 { token, target_type, target_id, reason, detail? }
出参 { code:0, msg:'ok', data:{ report_id, created_at } }
```

- `target_type` 必须 ∈ `['user','card','message','material']` → 否则 `code:400`「不支持的举报类型」
- `reason` 必须 ∈ `['harassment','fake','ad','other']` → 否则 `code:400`「请选择举报原因」
- `detail` ≤ 200 字（按 `Array.from().length` 数码点）
- 重复举报（唯一键冲突）→ `code:400`「你已经举报过了，我们会尽快处理」
- 不能举报自己 → `code:400`「不能举报自己」
- 写库前先查一次唯一键（不靠索引报错，索引线上还没建）

### 3.6 `message-search`

```
入参 { token, conversation_id, keyword, limit? }
出参 { code:0, msg:'ok', data:{ list:[…], total } }
```

list 项：`{ _id, sender_id, sender_name, type, content, created_at, is_me }`

- `keyword` 空 → `code:400`「请输入搜索关键词」
- 只搜 `type === 'text'` 且 `recalled !== true` 且 `created_at > cleared_at`
- 正则转义后做不区分大小写的包含匹配；`limit` 默认 20、最大 50，按 `created_at` 倒序
- 必须先取到 `cleared_at` 才能过滤
- 不是成员 → `code:403`

## 4. 既有云函数的改动

### 4.1 `message-send`

1. **黑名单拦截**（D2）：发消息前，找出会话里**另一个** `user_id`，查 `user_blocks` 是否存在 `{ owner_id: 对方, target_id: 我 }` → 存在则 `fail('对方已拒收你的消息', 403)`
   - 同时查 `{ owner_id: 我, target_id: 对方 }`（我拉黑了他）→ 也拦，`fail('你把对方加入了黑名单，无法发送', 403)`
   - 整段 try/catch，表不存在时当作没拉黑
2. `TYPE_ENUM` 加 `'voice'`；`voice` 类型额外接受 `event.duration`（秒，整数，1–60），写进消息文档的 `duration` 字段
3. 语音的 content 校验：非空即可（fileID）

### 4.2 `message-list`

1. 每条返回加 `recalled`（bool）、`recalled_at`（number）、`duration`（number，语音时长，非语音为 0）
2. `recalled === true` 时 `content` 下发空串 `''`
3. **按 `cleared_at` 过滤**：首次加载与增量加载都要 `created_at > myMember.cleared_at`
4. 返回体新增 `peer_last_read_message_id`（对方那一行的 `last_read_message_id`，没有则空串）。**放在 data 外层会破坏现有前端**，所以改成一个额外字段挂在同一返回对象上：
   ```js
   return { code: 0, msg: 'ok', data: out, peer_last_read_message_id: peerLastRead }
   ```
5. 顺手更新我这一行的 `last_read_message_id` 逻辑**保持不变**

### 4.3 `message-conversations`

1. 每个会话项新增：`pinned`（bool）、`muted`（bool）、`pin_locked`（bool）
2. `pin_locked` = 我和对方之间有 `buddy_relations.status === 'active'` 的关系（用已有的 `relationMap` 思路，别重复查库）
3. `pin_locked === true` 时 `pinned` 一律返回 `true`
4. **过滤掉我拉黑了的会话**：查 `user_blocks` 里 `{ owner_id: me._id }`，把 `target_id` 收进 `blockSet`，会话列表里对方在 `blockSet` 中的整行剔除
5. **排序**（服务端排好，前端不再排）：
   ```
   ① pin_locked === true 的排最前，按 last_at 降序
   ② 其次 pinned === true，按 last_at 降序
   ③ 其余按 last_at 降序
   ```
6. 若 `last_at <= 该会话我的 cleared_at`（清空之后对方没有发来新消息），**整行不返回**——清空 = 这段会话从我的消息页消失；清空后对方发来新消息（`last_at > cleared_at`）则**自动重新出现**并按正常排序归位（搭子强制置顶的会话同理）。被剔除的行不计入 `total_unread`
7. `total_unread` 统计**排除 muted 的会话**（免打扰不计入角标）

### 4.4 `user-profile`

1. 返回体新增 `is_blocked`（我拉黑了他，bool）、`blocked_me`（他拉黑了我，bool）
2. `is_blocked === true` 时 `can_invite` 一律 `false`，`reason` = `'你已把对方加入黑名单'`
3. `blocked_me === true` 时 `can_invite` 一律 `false`，`reason` = `'对方不接收你的邀请'`
4. 判定顺序：`is_self` → `is_blocked` → `blocked_me` → `isFriend` → 信誉 → pendingInv → `can_invite = true`
5. 整段 `user_blocks` 查询 try/catch，表不存在时都当 `false`

## 6. 项目铁律（写代码前必须看，违反即白屏/静默失败）

1. 用户集合名是 `'uni-id-users'`，**不是** `'users'`
2. 云函数业务错误一律 `return { code, msg }`，不 throw；内部 `fail()` 抛的错必须在 `exports.main` 末尾 try/catch 转成 `{code,msg}`
3. `.vue` 的 `<template>` 里**只能**引用 `data()`/`computed`/`methods` 上存在的东西。script 顶层 `const` 出现在模板里 → **整页白屏**。要用的常量必须挂进 `data()`
4. HTML 注释里不能出现 `<script>` 字面量
5. 云函数返回用户信息是**手写字段白名单**，加字段必须同步补白名单
6. 云函数/数据库用 snake_case；页面 `data` 用 camelCase。承接云函数返回值的容器字段允许 snake_case
7. 模板里调 methods 必须写 `this.xxx()`；**methods 内部调另一个 method 也必须写 `this.`**（漏写会抛 ReferenceError 导致跳转失效，本会话踩过）
8. `pages.json` 的 tabBar `fontSize`/`iconWidth`/`spacing`/`height` 只认 px；改 pages.json 后必须停掉运行重新运行
9. 判断状态用**显式布尔标记**，不要靠路径前缀/字符串猜测
