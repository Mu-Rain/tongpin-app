# 44 · 信誉系统改动说明（2026-11-14）

> 本文只讲「这次改了什么、为什么、要上传什么」。界面细节由前端会话调整，本文给的是**数据与接口的既定事实**。

## 一、一句话总览

信誉分从「只能看」变成「能涨也能扣」：新用户 90 分，<90 分不能发需求卡、不能申请搭子，只能靠做题恢复；聊天违规按情节扣 1~5 分，被放鸽子扣 1 分（须本人举报 + 签到记录为证），搭子互赞 +0.1，双方完成线下约见各 +0.1。

## 二、分值表（8 份云函数内的规则表已完全一致）

| 规则 code | 含义 | 分值 | 是否在用户端展示 |
|---|---|---|---|
| `rule_first` | 新用户首次学习《文明搭档守则》 | +5 | 是 |
| `quiz_pass` | 低于 90 分时做守则题 | +1.5 | 是 |
| `buddy_like` | 搭子互赞（每人一次） | +0.1 | 是 |
| `meetup_checkin` | 双方约见都签到 | +0.1 | 是 |
| `no_show` | 被放鸽子（举报成立） | -1 | 是 |
| `report_upheld` | 举报成立（默认情节） | -3 | 是 |
| `misconduct` | 不当行为 | -12 | 是 |
| `buddy_done` | 旧：成为搭子 | 0（停用） | 否 |
| `verify_pass` | 旧：认证通过 | 0（停用） | 否 |
| `admin_adjust` | 管理员手动调整 | 0 | 否 |

- 分数区间 0~100，**精度 0.1**（`clampScore()` 一律按 0.1 收口，避免出现 90.30000000000001）。
- 初始分 90；发需求卡、申请搭子的门槛都是 90。
- 停用的旧加分项**没有删行**，只是把分值改成 0：`buddy-complete` 等处仍按 code 调 `applyCredit`，删行会让那条链路直接抛错。
- `applyCredit` 现在遇到 0 分**不写流水**（否则「变动记录」被一串 +0 刷屏），但仍把当前分数原样返回给调用方（`verify-review` 靠这个值回填 `newCredit`）。

## 三、五块功能

### 1. 做题恢复（云函数 `credit-quiz`）

- 题库 40 题（7 类），首次调用自动播种到 `credit_quiz`；每次按类别轮流抽 10 题，**不下发答案**。
- 卷子有效期 2 小时；同一张卷只能交一次。
- 计分阶梯：**10 题全对拿满分，9 题 80%，8 题 60%，7 题及以下不得分**（也不扣分、不占当天次数）。
- 两种场景：
  - **新手特权**（`rule_first`，5 分）：不限分数，拿满 5 分才算用完；没拿满可以重考，**只补差额**（不然「9 题拿 4 分 + 重考 10 题拿 5 分」会变成 9 分）。
  - **每日一次**（`quiz_pass`，1.5 分）：只在当前分数 < 90 时可用，每天一次。

### 2. 举报与 AI 判级（`report-submit` → `report-screen` → `report-review` / `admin-reports`）

- 举报理由七类：`harassment`（骚扰谩骂）/`sexual`（色情或性骚扰）/`gambling`（赌博或毒品）/`fraud`（诈骗或广告）/`no_show`（放鸽子）/`misconduct`（不当行为）/`other`（其他）；老客户端的 `fake`/`ad` 自动映射到 `fraud`。
- 举报时**当场存证据快照**：消息类的最近 20 条、约局类的最近一次签到记录。理由：消息会撤回、记录会删，处置时再查往往已经空了。
- `report-screen` 两步走：先跑敏感词表（赌博/毒品/人身威胁 → 最重；色情 → 次重；诈骗/辱骂 → 较轻），**命中才调模型判轻重**（返回严格 JSON），结论写回 `reports.ai`；6 分钟内重复调用直接复用。它只判级、**不扣分**。
- 扣分发生在处置时（`report-review` 管理员判定）：优先级 = 管理员手填分值 > AI 判定的情节 > 规则默认值。
- 责任人改了：原来「卡片/消息被举报成立算内容责任、不扣账号」，现在按 `offender_id` 定位到**发消息的人 / 卡片主人 / 被举报人**，只有落在他身上才扣。

### 3. 搭子互赞（`buddy-like`）

- 双方各自可赞对方一次，+0.1，**只加不扣**（所以没有「取消赞」）。
- 五道防刷：不能赞自己；必须是 `active` 搭子关系；目标用户存在；**按人去重**（同一对用户只能互赞一次，哪怕他们挂了两段关系）；插入后回查一次，发现并发双写就删掉自己那条。
- 按人去重的原因：一个人可以同时有多段搭子关系（自习、夜跑），按关系去重等于能对同一个人点两次。

### 4. 约局签到（`meetup-invite` / `meetup-confirm`）

- 之前**全项目没有「发起约局」入口**，`meetup-invite`/`meetup-confirm` 一直是死代码。现在聊天页有 📅 按钮发约局卡。
- 约局表单的时间从「手填文本」改成**日期 + 时间选择器**：签到要判断时间窗，手写的「周六 19:00」没法比大小。`time_at`（毫秒时间戳）随卡落库。
- 发起时的校验：时间不能早于当前 1 小时以上、不能晚于 30 天。
- 到场判定：以约定地点为准，没有约定点就用对方签到位置；半径 **50 米**（10 米在室内 GPS 下不可行），定位精度最多放宽到 **100 米**（否则伪造一个巨大的精度值等于远程签到）。
- **签到窗口：约定时间前后 2 小时内**。老卡片没有 `time_at` 就不拦，避免旧数据被新规则卡死。
- 双方都签到 → 各 +0.1（按人各发一次、按约局幂等，失败不回滚签到本身）。
- 被鸽：**不由系统自动扣分**，必须当事人自己举报 `no_show`，后台看到签到记录（谁到了、谁没到、距约定点多少米）再决定是否成立 → 成立扣发起/被约方 1 分。
- **当事人限制**：举报 `no_show` 时后端会核对「我和被举报人之间确实存在一局约局」，没有记录直接拒绝（提示「你们之间没有约局记录，「放鸽子」只对真约过的人成立」）。避免任何人拿这个理由给别人扣分。

### 5. 旧加分机制下线

按你的要求「旧的加分方式舍弃、但双方签到 +0.1」：`buddy_done`、`verify_pass` 两条旧加分统一置 0 并从用户端规则表隐藏；新增 `meetup_checkin` 0.1。用户端的「加分详情」现在只会出现：首次学守则 +5、做题 +1.5、搭子互赞 +0.1、约见签到 +0.1。

## 六、回归验证清单

1. 新用户注册 → 信誉分显示 90。
2. 做守则题：10 题全对 +5；9 题 +4；8 题 +3；7 题 0 分且当天次数不消耗。
3. 拿满 5 分后再进做题页 → 提示只有「低于 90 分才能做题」。
4. 把分数降到 89（可用后台手动调整）→ 发需求卡 / 申请搭子被拦，做题可 +1.5。
5. 举报一条辱骂消息 → 后台能看到 AI 判级与证据；判定成立扣**发送者** 1~5 分。
6. 搭子页点赞 → 对方 +0.1；再点一次提示已赞；换一段关系再赞同一人仍被拒。
7. 发约局（选日期+时间+地点）→ 到点前后 2 小时内两边各点「我已到达」→ 双方都 +0.1；窗口外点会提示不在签到时间内。
8. 举报 `no_show` → 后台能看到「谁到了、谁没到、距约定点多少米」；对着**没约过的人**报会被直接拒绝。

## 七、已知没做 / 待定

- 旧加分项的**历史流水**不会删，仍会显示在变动记录里（只是不再产生新的）。
- 互赞与签到的加分**不发通知**，靠信誉分页的变动记录查看（你的选择）。
- 举报成立与否仍是人工判定，AI 只给出情节建议。
- 信誉分低于 90 的**具体拦截文案**由前端会话统一措辞。
