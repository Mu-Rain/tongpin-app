> **踩过的坑，记下来免得重犯**：
> 1. **集合名必须写 `uni-id-users`，不是 `users`**。第 1 天注册时用户写进了 `uni-id-users`，第 3 天的 `card-publish` / `card-list` 却去查 `users`，查出零行 → 误报「登录已过期」。**所有查用户的云函数统一用 `const DB_USERS = 'uni-id-users'`。**
> 2. **云函数改了必须「上传部署」再真机验证**。HBuilderX 右键菜单里「运行-云函数测试」会去找 `*.test.js`（我们没写，必然失败），别点错。
> 3. **HBuilderX 占着文件时，`edit` 会报 `ReplaceFileW EIO (Win32 1175)`** —— 重试一次即可，别以为文件坏了。
> 4. **云函数的业务错误走 `code`，不是 throw**。`uniCloud.callFunction` 只有在网络/函数崩溃时才 reject；`{ code: 401, msg: '未登录' }` 是**正常返回**。所以客户端必须判断 `r.code !== 0` 并自己抛错，否则失败会被当成成功（第 5 天在 transport.js 里修的就是这个）。
> 5. **字段命名两套并存**：云函数内部/返回用 snake_case（`client_msg_id`、`buddy_tag`），页面 data 用 camelCase（`clientMsgId`）。跨层时要么统一、要么两边都兜底读，别假设它们同名。
> 6. **聊天分页：进页面全量拉，轮询才增量**（第 5 天连改三轮才定下来，代价最贵的一条）。曾经用本地缓存 `chat_last_<用户>_<会话>` 记住"上次看到哪儿"，想在重进时只补新消息。但这个起点会随每条新消息**一路往前跳**，跳到最新一条后服务端就没有"比它更新"的消息 → 返回空数组 → **聊天页越进越空**。根因是把两件需求相反的事共用了同一个起点：进页面要"最近 N 条完整历史"，轮询要"比上次新的"。现在的规则是：`initChat` 里 `lastMessageId` 固定传 `''`（全量）；增量起点只活在 `transport.js` 的内存变量里，页面一关就失效，**不落本地存储**。同理 `transport.send()` 成功后**不许**推进 `lastMessageId` —— 唯一的推进点是 `fetchSince` 拉到消息时。
> 7. **诊断聊天类 bug 时先问"第几次进入"**。这个 bug 表现为"随机丢消息"，实际是一条单调递减曲线（第 1 次 3 条、第 2 次 1 条、第 3 次 0 条）。用户描述"第一次/第二次/第三次分别看到什么"比截图有效得多。看录屏时也要抽高帧率重放，1fps 的九宫格会把"发完消息的瞬间历史被顶掉"这个关键帧漏掉。
> 8. **云函数返回用户信息时是手写白名单，新加字段必须同步补进白名单**（第 7 天最贵的一课）。`user-login/index.js` 返回 `user` 时逐个字段挑，数据库里加了 `role` / `is_admin` 但白名单没加，于是 App 永远拿不到 → 管理员卡片不显示、审核接口 403。**改任何"让 App 读到新字段"的需求，第一件事是查白名单，不是查数据库。** 同理：本地缓存 `userInfo` 是登录那一刻的快照，改库不会自动同步，需要 `user-me` 云函数按 token 重拉。
> 9. **同一份数据写两处，必然有一处漂移**。`card-apply` 同意申请时建了 `conversations` 并把 id 回写 `applications`，却忘了写 `buddy_relations`，导致详情页能进聊天、我的搭子页说"没有会话"。现在两处都写（`card-apply` 第 5.5 步写 applications、5.6 步写 buddy_relations），`buddy-list` 还加了反查 conversations 的兜底与历史数据回填。
> 10. **`pages.json` 里 tabBar 的 `fontSize` / `iconWidth` / `spacing` / `height` 只认 px，写 rpx 会导致整条 tabBar 静默消失**。现象很迷惑：底部留出一条白色空白、没有任何报错，`unpackage/dist/dev/app-plus/app-service.js` 里也能 grep 到图标路径（说明配置读进去了），但就是不渲染。原因是 tabBar 是**原生层**渲染的，rpx 是页面样式层才认识的相对单位，原生层解析失败就整体丢弃。正确写法 `"fontSize": "11px", "iconWidth": "22px", "spacing": "3px", "height": "50px"`（`app-plus` 下还可写 `"safearea"`）。**改 pages.json 后必须停掉运行重新运行**，热更新不会重建原生 tabBar。
> 11. **一对多关系不能靠"再建一条会话"来实现**（第 8 天丙方案）。现象：A 和 B 已经是搭子，双方仍能各自发卡、互相申请、再同意一次 → 同一对人出现第二条 conversation，聊天列表出现两份、两边各看一半。根因：会话的创建挂在「卡片被同意」这个**事件**上，而同一对人在不同卡片上可以被同意 N 次，会话表没有任何「一对主体」的唯一约束。修法不是拦截，而是改入口：① **一对人全局只有一条 direct 会话**（建之前按 `user_a_id / user_b_id` 且 a<b 查一次，有则复用）；② 多段搭子关系改由「进对方主页 → 定向邀请」产生，接受后只在 `buddy_relations` 多一条记录、**不新建会话**；③ 聊天列表把同一对人多条关系**合成一张卡**（标签拼成「啊哈哈搭子 · 夜跑搭子」）；④ 聊天页顶点对方头像进主页，这是再约一段关系的唯一入口。**教训：凡是「一个事件对应一条记录」的建表，先问"这个事件能对同一对主体发生几次"，能发生多次的，唯一性要建在主体上，不能建在事件上。**
> 12. **`.vue` 模板里不能直接用 `<script>` 顶层的 const / function，必须挂到 `data()` 或 `methods` 上**（第 8 天白屏）。现象：一点「接受邀请」整页白屏，红字 `Property "TAG_COLORS" was accessed during render but is not defined on instance` + `TypeError: Cannot read property 'shine-yellow' of undefined`。根因：模板渲染函数的上下文是组件实例，`TAG_COLORS` 是模块级 const，实例上没有这个名字 → 渲染函数崩掉 → 整页白。修法：模板里改调 `methods` 的 `colorHex(k)`。**要记住的是扫描方法**：写脚本查"模板用了 X 但 data 里没有 X"时，`data` 里既可能是 `X: X,` 也可能是 ES6 简写 `X,`，只认前者会**大面积误报**（本项目第一次扫描就误报了 buddy / hall / publish 三个正常页面）。
> 13. **HTML 注释里不能出现 `<script>` / `</script>` / `<style>` 这些字面量**（第 8 天，差点铸成大错）。我在 `<!-- ... -->` 里写了一句解释，其中含 `<script>` 三个字，结果 Vue 的 SFC 编译器在 `-->` 之前就把它当成真正的 script 开始标签解析 → 文件出现两个 script 开始标签、一个结束标签 → **整个页面编译失败**。这个坑极隐蔽，因为它只在"写注释解释 script 内变量"时触发，而检查脚本若也按正则抽 `<script>(.*?)</script>`，会因为注释里那次匹配而抽到错误片段、报出**假的**语法错误（我一开始就以为是代码写错了）。正确做法：先 `[regex]::Replace($s, '(?s)<!--.*?-->', '')` 剥掉 HTML 注释再抽 script；写注释时把 `<script>` 写成「script 标签」四个字，别写字面量。

## 4. AI 协作铁律（这 6 条决定你会不会翻车）

1. **一次只让 AI 做一个小块**，并且**先告诉它验收标准**（就是把 US-xx 那条贴过去）。
2. **给它上下文**：相关集合结构（DB Schema）、已有云函数、报错全文。**云函数名、spaceId 这类非密钥信息可以贴**，贴着它才写得对。没有上下文它一定瞎写。
3. **要求最小改动**："只改这个文件、只加这个方法，不要重构其他地方"。
4. **先跑再信**：AI 说"完成"不算完成，真机点通才算。
5. **不加自己看不懂的代码**：看不懂就让它解释，解释不清就重写成简单版本（答辩会被问）。
6. **绝不把密钥给任何人**：DeepSeek Key **只写在云函数的环境变量里**；**不要贴进任何 AI 对话**（包括我），**也不要提交进 Git**。uniCloud 的 `spaceId`、云函数名、集合名这些**不是密钥**，可以贴。

| **AI 生成的代码用了小程序不支持的写法** | 真机/浏览器预览时报错或白屏，常见 `div is not defined`、样式全乱、`document is not defined` | 把**模板 3 的"硬性要求"整段贴给 AI**让它改写；记住三板斧：`view/text` 替 `div/span`、`rpx` 替 `px`、`@tap` 替 `@click`。搜不到答案就搜"uni-app + 报错关键词" |
