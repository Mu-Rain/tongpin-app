## 1. 导航结构

底部 4 个 tab（**只有这 4 个一级页显示 tabBar**）：

```
[ 首页 ]   [ 同频圈 ]   [ 消息 ]   [ 我的 ]
```

- **首页**：便当格布局（尺寸规则见 §1.1）、每日百科顶部细条、我的搭子速览。
- **同频圈**：占的是原「大厅」tab 的位置（**暂定名，用户可随时改名**）；**同校 / 地区 / 发现** 三栏切换的日常内容流（P26，本期只做占位原型；「地区」= 同城·周边，「发现」= 全国）。
- **消息**：会话列表（含 AI 机器人固定会话）；底部有「我的搭子与标签 →」按钮，进 P28。
- **我的**：资料、认证状态、信誉分明细、称号墙、我的搭子 / 好友、设置。
- **发布**：**已取消原来悬在首页右下角的悬浮按钮**。发布入口只在**搭子大厅页内部**：大厅顶部一个「发布搭子需求 ＋」大按钮（副文案「每天最多 5 条」），点开同一个发布抽屉；大厅以外的页面不再有发布入口。
- **搭子大厅**：不再占底部 tab，降级为**首页下的子页面**（左上角返回）。
- **二级页面不显示 tabBar**：进入 搭子大厅、学习、健身、需求详情、匹配结果、学生认证、称号库、聊天、发一条日常、我的搭子 后底部 tabBar 不再出现，只靠左上角返回；回到 首页 / 同频圈 / 消息 / 我的 这 4 个一级页时才恢复。

### 1.1 首页「便当格」布局与尺寸规则（2026-10-16 新增）

便当格 = 卡片网格，但**板块尺寸刻意不统一**，越重要的块越大：

| 板块 | 尺寸规则 | 点击去向 |
|---|---|---|
| 搭子大厅 | **最大的一块**，独占首屏主位，是首页**唯一主入口**；内含 学习搭子 / 健身搭子 / 拍照·逛校园 / 竞赛搭子 四个方向 + 一键匹配 | P04 搭子大厅（子页面，左上角返回） |
| 学习 | **与健身一样大**：两个并排的半宽卡（各占一半宽） | P14 学习 & 番茄钟 |
| 健身 | **与学习一样大**：两个并排的半宽卡 | P12 健身与打卡 |
| 心理疏导 | 预留板块：**虚线边框的占位卡**（尺寸小于学习 / 健身） | P27 心理疏导（AI 对话） |
| 每日百科 | **顶部细条**（一行高） | P16 每日百科 |

> 原来首页那四个独立入口（找学习搭子 / 找健身搭子 / 拍照·逛校园 / 一键匹配）**全部并入搭子大厅**，不再各自占一块。

## 3. 核心流程

### 3.1 主链：找搭子 → 建立关系 → 聊天

```mermaid
flowchart TD
  A[打开 App] --> B{已登录?}
  B -- 否 --> C[登录/注册] --> D[完善资料+标签]
  B -- 是 --> E[首页便当格 -> 搭子大厅]
  D --> E
  E --> F{自己发 还是 找现成?}
  F -- 发 --> G[填写卡片并发布]
  F -- 找 --> H[搭子大厅/一键匹配]
  G --> I[卡片出现在大厅]
  H --> J[按标签重合度排序出结果]
  I --> K[他人浏览卡片详情]
  J --> L[点卡片详情]
  K --> M[点 我想搭]
  L --> M
  M --> N[对方收到申请]
  N --> O{对方同意?}
  O -- 否 --> P[提示被拒绝, 可继续匹配]
  O -- 是 --> Q[建立搭子关系]
  Q --> R[自动开会话/进入聊天]
  R --> S[设置搭子自定义标签 + 闪亮色]
  S --> T{想升级?}
  T -- 是 --> U[好友申请 -> 同意 -> 好友]
  T -- 否 --> V[完成搭子 -> 双方确认 -> 信誉+2]
```

### 3.2 学生认证

```mermaid
flowchart LR
  A[未认证用户] --> B[点同校频道]
  B --> C[提示: 认证后可进入]
  C --> D[上传学生证照片]
  D --> E[状态: 审核中]
  E --> F{后台审核}
  F -- 通过 --> G[加认证标识]
  G --> H[解锁同校频道]
  F -- 拒绝 --> I[填写理由] --> D
```

### 3.3 聊天链路（消息表 + 3 秒轮询，传输层可替换为 WebSocket）

> 设计细节见 [06-chat-transport.md](./06-chat-transport.md)。页面只调用 `createChatTransport()` 返回的接口，**不关心底层是轮询还是 WebSocket**。

```mermaid
sequenceDiagram
  participant U as 用户A(App 聊天页)
  participant C as 云函数 message-send
  participant D as 云数据库 messages
  participant V as 用户B(App 聊天页)

  Note over U: 点发送
  U->>U: 本地乐观插入一条"发送中"气泡（带 clientMsgId）
  U->>C: 调云函数写入消息(conversationId, content, clientMsgId)
  C->>D: 按 clientMsgId 去重后写入 messages
  D-->>C: 返回服务端消息（_id + 服务端时间）
  C-->>U: 返回 { code:0, data:{ 消息 } }
  U->>U: 用 clientMsgId 找到本地那条，状态改为"已送达"

  Note over V: 进入聊天页立即拉一次
  V->>C: 拉最新消息(lastMessageId = 空)
  C->>D: 查询该会话最新 N 条
  D-->>C: 消息列表
  C-->>V: 返回消息列表

  loop 每 3 秒（仅在聊天页活跃时）
    V->>C: fetchSince(lastMessageId)
    C->>D: 查询 _id/时间 大于 lastMessageId 的消息
    D-->>C: 增量消息
    C-->>V: 返回增量消息
    V->>V: 追加到列表 + 更新 lastMessageId + 更新未读数
  end

  Note over V: 离开页面 → 立即停止轮询
  Note over V: App 不在前台/锁屏 → 靠 uni-push 提醒"有新消息"
  Note over V: 断线重连 → 用 lastMessageId 补拉，不丢消息
```

## 4. 交互约定（每个页面都要做到）

| 场景 | 约定 |
|---|---|
| 加载中 | 骨架屏或转圈，不能白屏 |
| 空列表 | 一句话说清 + 一个可点的下一步（例："还没有搭子，去大厅看看"） |
| 出错 | 一句话人话提示 + 重试按钮；技术错误不直接给用户看 |
| 断网 | 顶部横条"网络不可用"，恢复后自动重试上一次请求 |
| 提交类操作 | 按钮进入 loading 并禁用，防止重复提交 |
| 删除 / 解除 | 二次确认弹窗，说明后果 |
| 权限 | 相册 / 通知 / 定位被拒绝时，说明用途并给"去设置"入口 |

## 5. 权限与隐私（上架 / 答辩都会被问）

| 权限 | 用途 | 何时申请 |
|---|---|---|
| 相册 / 相机 | 头像、学生证、聊天图片、资料、同频圈发日常（P2） | 用户点上传时申请 |
| 通知 | 健身提醒、新消息 | 用户开启提醒时申请 |
| 定位 | "附近"范围（不用于判定学校，见待确认项 D2） | 用户切到"附近"时申请 |

隐私页必须写清：收集什么、为什么、保存多久、怎么删除；提供账号注销入口。
