## 2. 视觉约定（这几条是最容易做错的地方）

### 2.1 描边分两类，绝不能混用

| 场景 | 用哪个 | 为什么 |
| --- | --- | --- |
| 玻璃面自己的外缘 | `--tf-line`（白 85%） | 这是玻璃的「厚度」高光 |
| 压在浅底上的任何描边 | `--tf-line-soft`（墨 8%） | 白色在浅底上等于没有 |

当前 `var(--tf-line)` 只剩 **19 处**：`App.vue` 2 个玻璃类 + 14 条 `.card` + `.buddy-card` + 2 处 `.shiny-tag`。
**页面里除了「玻璃面自己的边」，不该再出现它。**（`var(--tf-line-soft)` 目前 74 处）

### 2.2 「浮起」效果（lift）· 两档

粗野主义的实心偏移投影，但颜色压成暗墨、且分两级高度：

```css
/* 大档：整块浮起来的元素 */
border: 2rpx solid var(--tf-lift-line);
border-radius: var(--tf-r-md);
box-shadow: var(--tf-lift);        /* 4rpx 4rpx 0 / .50 */

/* 小档：按钮、徽章这种小元件 */
border: 2rpx solid var(--tf-lift-line);
border-radius: 999rpx;
box-shadow: var(--tf-lift-sm);     /* 2rpx 2rpx 0 / .42 */
```

**为什么要分两档**

- **层级**：气泡是内容主体，要浮得最高；按钮是气泡里的操作，浮低一点才不抢戏。同偏移量会让一屏出现十几个一样高的「台阶」。
- **比例**：4rpx 偏移放在 60rpx 高的小按钮上显得笨重，放在 200rpx 高的图片上才协调。

**描边必须共用 `--tf-lift-line`（.44）**
描边比阴影浅，圆角处会露出「接不上」的缺口。`.44` 刻意夹在大档 `.50` 和小档 `.42` 中间 —— **描边不能比小档还浅**，否则小按钮的圆角会先露出缺口。

**归档规则**：高度 ≥ 100rpx 或整块卡片 → 大档；按钮 / 徽章 / chip / swatch → 小档。

> 一屏实心投影别超过 6 个，否则右下实心边会连成暗带显脏。

### 2.3 文字三级浓度（阶段 3 定稿）

效果图用 4 级（`--ink` / `ink-2` .60 / `ink-3` .40 / `ink-4` .22），但那是**视觉稿**，`.40` 在真机上只有 2.4:1，小字会糊。移植后按 WCAG 反推重定：

| 级 | 令牌 | 值 | 对比度 | 只给 |
| --- | --- | --- | --- | --- |
| 一级 | `--tf-text` | `#16212E` | 15.9 : 1 | 标题、正文主体 |
| 二级 | `--tf-text-2` | `.62` | 4.5 : 1 | 说明 / 副标题 / 时间 / 状态 / 提示 |
| 三级 | `--tf-text-3` | `.52` | 3.3 : 1 | **箭头 / 占位符 / 调试开关**（纯装饰） |

**判断规则**：这段字**读不读得到会影响用户做决定**吗？
- 会 → `--tf-text-2`
- 不会（纯装饰）→ `--tf-text-3`

阶段 3 之前 text-3 有 234 处，绝大多数是「时间、状态、说明」这类该读的字。现在只剩 31 处箭头、占位符和装饰点。
**新写样式时默认用 `--tf-text-2`，别顺手写 text-3。**

### 2.4 必须不透明的地方

主按钮（用 `--tf-primary` 实色）· 输入框（`rgba(255,255,255,.96)`）· 对方聊天气泡（本方案给玻璃，但文字多的要加白内衬）

**例外**：压在滚动内容之上的工具条（`chat` 的 `.chat-input` / `.search-panel`）用 `--tf-card-strong` + `backdrop-filter: var(--tf-glass-blur)`。不透明会像贴了一块塑料，只半透明不加模糊则身后的字会跟工具条的字叠在一起 —— 必须两者同时上。

### 2.5 单位与边框

- px × 1.923 = rpx
- 边框写 **`2rpx` 不写 `1rpx`**：2rpx ≈ 1px；1rpx 在部分安卓上渲染成半像素，白边变灰色虚线

### 2.6 深色底块的处理

效果图 `style.css` 里**一个深墨底块都没有**。所以全站 `background: var(--tf-text)` 的近黑块统一映射成 `var(--tf-primary)` 靛蓝实色：

- `tags.vue` `.summary`、`verify.vue` `.status`（深色主卡）
- `buddy.vue` `.chip--on`、`hall.vue` `.filter--on`（选中态）
- `workout.vue` `.finish-btn`（主按钮）

> 这三处「选中态 / 主按钮」是阶段 3 才发现的，粗野主义 grep 抓不到（它是 background 不是 border/shadow）。
> **查深墨底要单独跑**：`grep -rn "background[a-z-]*: var(--tf-bg)\|background[a-z-]*: var(--tf-text)" app/pages`，预期只剩前者。

### 2.7 页面根容器必须透明（否则渐变白做）

`App.vue` 的 `page{}` 上有 5 层渐变（四角光斑 + 线性）。但**每个页面的 `.page` 都写过
`background-color: var(--tf-bg)`** —— 不透明，把渐变整块盖住了。

后果：阶段 1 做的渐变底**一次都没显示过**，玻璃后面是一片平色 `#EEF4F6`，
所以「液态玻璃」看起来像「半透明白卡片」。

**规矩**：页面根容器（`.page` / `.chat-wrap` 等）一律 `background: transparent`，
渐变只由 `page{}` 提供，页面里不要再写底色。

2026-10-25 已批量修 27 处（26 个 `.page` + `chat` 的 `.chat-wrap`）。

> 例外：页面内的 chip / 输入框 / 分段控件用 `--tf-bg` 做**填充**是正常的，那是元件底不是页面底。
> 判断标准：这个元素是不是铺满整屏？是 → 必须透明。

#### 4.4.1 两处偏离设计稿的地方（都做了诊断，不是随手改的）

设计稿的 tabBar 是在**深紫背景**上做的，我们的页面是浅冷底。照抄会出两个问题，
用 A/B/C 三栏诊断页比过（`saturate` 1.9 / 1.0 / 1.2）：

| 参数 | 设计稿 | 实际采用 | 原因 |
| --- | --- | --- | --- |
| 底槽底色 | `rgba(255,255,255,.12)` | `var(--tf-card)`（白 55%） | 浅底上 0.12 和背景糊成一团，边框也看不见 |
| 底槽边框 | 白 `rgba(255,255,255,.42)` | `var(--tf-line)`（白 85%） | 同理，浅底上弱白边读不出来 |
| 滑块底色 | `rgba(255,255,255,.11)` | `rgba(255,255,255,.62)` | 滑块是选中态的实体表达，太淡只剩一道白边 |
| 两层 `saturate` | 1.9 / 1.95 | 都改成 **1.2** | tabBar 背后是页面渐变本身，1.9 会把渐变里的蓝绿色斑放大，**整条栏发青** |

> **教训**：`--tf-glass-blur`（saturate 1.9）是给**卡片**调的 —— 卡片背后是白色内容。
> 但 tabBar 背后是**页面渐变本身**，同一个值会把色斑放大。
> **判断标准：这个玻璃元素背后是什么？** 是内容 → 1.9；是渐变 → 压到 1.2。

**没做的：消息 tab 未读红点。** 设计稿上是红点 3，但项目里没有全局未读数据源
（未读数由 messages 页自己算，不落存储），tabBar 组件读不到。

        for x in range(w):
            q=r[x*4:x*4+4]
            if q[3]>200: c[q[:3]]+=1
    return c.most_common(1)[0][0]
