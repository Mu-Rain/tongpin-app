## 五、踩过的坑（别再踩）

### 1. `.deal` 缺 `box-sizing: border-box` ← 最严重

`height: 400rpx` + `padding: 100rpx` = 实际 **500rpx**，比展开间距还高，卡片互相重叠。

**只在内容长的时候暴露**（短描述测不出来）。我的 HTML 验证页也没写 box-sizing，所以没发现。

### 2. `v-show` + null 解引用 → 白屏

```html
<view v-show="sheetCard">  <!-- 元素始终渲染 -->
  {{ sheetCard.owner.nickname }}  <!-- null.owner → 报错 → 整页白屏 -->
```

用 `v-if`。**`v-show` 会渲染内容，模板里不能有依赖数据非空的解引用。**

### 3. sticky 元素上的负 margin 不产生位移

试了三种全失败：`.stats { margin-top:-29px }`、`.hero { margin-bottom:-29px }`、`calc()`。
正解：`transform: translateY(-29rpx)` + `margin-bottom: -29rpx` 抵消布局空隙。

### 4. `calc()` 的除数不能是负数

`calc(58px / -2)` 整条失效，要写 `calc(58px * -0.5)`。

### 5. 删 `transition` 换性能 → 抖动加剧

高度是 JS 每帧给的**离散值**，没过渡就是阶梯跳变。
**「减少更新次数」≠「更平滑」**，平滑靠过渡。三个过渡都不能删：
```css
.hero { transition: height 120ms linear }
.deck { transition: height 120ms linear }
.deal { transition: transform 120ms linear }
```

### 6. z-index 拍脑袋 → 反被盖

给 `.sec-row` 加 `z-index:10`（想盖住卡片），但数字卡只有 `6` —— 标题行反过来盖住了数字卡。
**加层级前先把所有相关元素列出来排一遍。**

### 7. 两个元素抢同一块区域 → 调 z-index 治不好

标题行和数字卡都要"贴着头"，滚动时必然撞。**真正的解法是让它们不抢**——把标题行合并进头图，跟着一起走/一起淡出。

### 8. 截图字节数相同 = 渲染没变

改代码后截图大小一模一样，说明改动不产生视觉差异（不是缓存）。用「把背景改成红色」做对照实验确认渲染管线。

## 七、工作方式（用户偏好）

### 用户怎么提需求

- 先要**效果图**，确认后再落地代码
- **"这些只是加动效，基于已经确定的设计元素再添加，不要改掉刚才已经设计好的东西"** ← 原话，很重要
- 会发**参考图/截图/录屏**，说"注意看 xx"

### 用户在意什么

- **视觉层次**：一叠卡要能看出是"一叠"
- **语义准确**：同频圈是发动态的地方，不是找搭子（我搞错过一次）
- **滚动要平顺**：抖动会被明确指出
- **组件不要互相遮挡**：反复强调层级

### 我的验证方法（很有效，继续用）

**uni-app 跑不起来时**：
1. 从 `.vue` 里 `re.search(r'<style[^>]*>(.*?)</style>')` 抽样式
2. rpx 按 `×0.52` 换成 px
3. 配静态数据 + 复刻滚动逻辑，渲染成 HTML
4. Edge headless 截图（`--force-device-scale-factor=2`）

**⚠️ 验证页必须加 `*{box-sizing:border-box}`，并且用真实长度的文案** —— 否则测不出 box-sizing 类问题。

**看录屏**：
