## 3. 云函数契约（改 UI 不能改这些字段名）

### 3.1 `buddy-list` —— 我的搭子（1077 行页面 + 该函数）

入参：`{ token, status? }`（`status` 不传默认只查 `active`）
出参：`{ code, msg, data: { list: [人…], total } }`

**★ 一条 `list` 项 = 一个人，不是一条关系。** 同一对人在不同 category 下可以有多段搭子关系（自习 + 夜跑 + 拍照），界面上必须有且只有一张卡，卡里并排显示这段关系产生的**全部标签**。合并已经在服务端做完，前端不要再自己按人合并（消息页、聊天页以前各实现过一遍，都漏了）。

每个人：

```
other_user_id / name / avatar / school / credit / verified
conversation_id                 ← 一对人全局唯一，点卡片进这一个会话
last_text / last_at             ← 会话摘要
since                           ← 最早一段关系的建立时间
tags: [{ relation_id, label, color, category, category_label, since,
         my_done, peer_done, done_count }]   ← 我给他起的全部标签
tag_count
```

- 兼容字段：`my_label` / `my_label_color` / `relation_id` 取 `tags[0]`。
- 「搭子」两个字是**固定后缀，由前端拼**；库里存和接口返回的都是前缀（如 `夜跑` → 界面显示 `夜跑搭子`）。
- ★ 搭子标签是**私有备注**：只返回我这一侧的 `label`，绝不下发对方的（不返回 `his_label`）。UI 上不要设计成「双方都能看到同一句备注」。

### 3.2 `my-liked` —— 喜欢（357 行）

入参：`{ token, page = 1, page_size = 20（上限 50） }`
出参：`{ code, msg, data: { list, total, has_more } }`

```
list[]: {
  kind: 'card' | 'post',
  target_id,
  title,        cards 取 title；posts 没有标题字段，固定 ''
  summary,      cards 取 description；posts 取 content（**原样给，截断由前端做**）
  cover,        images[0] 换成 https 临时链接；没图/换不出来都是 ''
  like_count,   number
  created_at,   number  内容的创建时间
  liked_at,     number  **我点赞那一刻**的时间
  alive,        bool    false = 内容已删除/下架（仍返回，前端置灰但可点）
  owner: { _id, nickname, avatar_url }
}
```

两个必须理解的口径：

1. **排序键是 `liked_at`**（我点赞的时间），不是内容时间。界面上的时间也应该显示 `liked_at`，否则列表看起来是乱的。
2. **已删除的内容不剔掉**（`alive: false`）。剔掉会让 `total`、`has_more` 和翻页数字一路漂移。正确做法：保留占位、显示「内容已删除」、置灰。

### 3.3 `recommend-list` —— 为你推荐（344 行）

入参：`{ token 可选, scope = 'school' | 'city' | 'all', page = 1, page_size = 10（上限 30） }`
出参：`{ code, msg, data: { list, total, has_more, degraded, page } }`

```
list[]: { kind, target_id, title, summary, cover, like_count, created_at,
          owner: { _id, nickname, avatar_url } }
degraded: '' | 'no_school' | 'empty_school' | 'no_city' | 'empty_city'
```

- `degraded` 是「推荐降级了」的说明，现在 recommend.vue 已经把它渲染成一行灰字（`degradedText`）。**UI 必须保留这个位置**：降级了却不说，用户会以为推荐坏了。
- `total` 是当前生效口径下的候选条数（两张表相加，已排除自己发的内容）。
- 已登录才有页面内的登录门（三页统一策略：未登录不发请求）。

### 3.4 `browse-list` —— 观看历史（361 行）

入参：`{ token, page = 1, page_size = 20（上限 50） }`
出参：`{ code, msg, data: { list, total, has_more } }`

字段与 `my-liked` 相同，只有一处差别：**时间字段叫 `viewed_at`**（我浏览那一刻）。

写入方是 `browse-record`（`{ token, target_type: 'card' | 'post', target_id }`），由 detail.vue:391 与 post-detail.vue:189 在**内容加载成功之后**调用（失败的 id 不该进历史）。

### 3.5 `home-summary` —— 首页数字卡（193 行）

出参：`{ matched_total, people_total, my_open_cards, my_buddy_count, my_avatar_url }`
前四个是 `number | null`，**算不出来一律给 null，绝不给 0**：

- `0` = 真的是零（确实没发过需求 / 确实没有搭子）
- `null` = 不知道（未登录、查询失败）→ 界面上应该显示 `-` 或不显示

mine.vue:55 就是这么做的：`{{ buddyCount === null ? '-' : buddyCount }}`。**不要用 `|| 0` 兜底**，那会把「不知道」变成「你没有搭子」。

## 5. 你可以改 / 不能改的边界

**可以改（鼓励改）**：卡片形态、封面比例、字号层级、间距、分隔方式、图标、骨架屏样式、空态插画与文案、失败态样式、下拉刷新视觉、列表分组/筛选条的视觉。

**不能改（改了会断）**：

1. 云函数名、入参名、返回字段名（第 3 节那些）。要加字段先提，别在前端 `map` 出同名假字段。
2. `alive === false` 的项**必须保留并且可点**，只做置灰 + 「内容已删除」标识。
3. 三态（未登录 / 加载中 / 失败）+ 空态必须齐全，**任何一种都不许白屏**。
4. 头像统一走：有 `owner.avatar_url` 就 `<image>`，没有就 `/static/avatar-default.png`（全站唯一默认头像，四角透明、圆盘贴满画布，**不要再画新的默认头像**）。
5. 列表页的 `PAGE_SIZE`、`onPullDownRefresh`、`onReachBottom` 逻辑保留（只改视觉不动取数）。
6. **不新增云函数、不新增集合**。这四个功能的后端已经齐了，再加接口等于重复造。

## 6. 工程约束（都是踩过的坑，照做省一轮返工）

1. 项目是 **Vue 3**。不要用 `?.` 和 `??`，也**不要用 `this.$set`**（Vue 3 实例上可能不存在，抛错会被外层 catch 吞掉）。
2. 尺寸用 `rpx`，颜色用主题变量（定义在 `dazi-app/app/App.vue`）：
   `--tf-bg` / `--tf-card` / `--tf-card-strong` / `--tf-card-line` / `--tf-line` / `--tf-line-soft` / `--tf-primary` / `--tf-primary-deep` / `--tf-primary-soft` / `--tf-text` / `--tf-text-2` / `--tf-text-3` / `--tf-danger` / `--tf-r-sm` / `--tf-r-md` / `--tf-r-lg` / `--tf-glass-blur`。**不要写死色值**，换肤会全崩。
3. 修饰类（`.avatar--img` / `.avatar--def` / `.acc-avatar--img`）必须写在**基类之后**：两个单类选择器同权重，由源码顺序决定谁生效；写在前面会被基类的 `background` / `display:flex` 盖掉。
4. 安全区写法**先旧后新**：
   ```
   padding-bottom: calc(24rpx + constant(safe-area-inset-bottom));
   padding-bottom: calc(24rpx + env(safe-area-inset-bottom));
   ```
5. 改完必须**全工程**自检，不能只检查自己改的文件：
   - 47 个 `.vue` 抽 `<script>` 逐个 `node --check`；
   - 每个 `<style>` 大括号配平。
   理由：`pages/tags/tags.vue` 曾经多出两个 `}`，与本次改动毫无关系，却让**整个工程编译失败**、手机一直跑旧包，白查了半天。教训写在 docs/28 §22.2。
6. `pages.json` 是**纯 LF** 行尾（不是 CRLF），插入路由时别用 `\r\n` 做锚点。
7. 别把浮层的 `z-index` 放到输入栏之下 —— `chat.vue` 的「…」更多菜单曾因为**三组样式整个没写**，把三条文案按普通块级流甩在输入栏下面。

## 7. 这四个功能**不包含**什么（别设计不存在的入口）

- 「喜欢」≠「收藏」：收藏是 `/pages/favorites/favorites`（收藏的搭子卡），两条数据链完全独立。
- 「推荐」不推荐人；也没有「不喜欢 / 减少此类推荐」的反馈机制（未做）。
- 「观看历史」不含同频圈信息流的滚动曝光，不含聊天记录；也**没有「清空历史」入口**（未做，若要做得先加云函数）。
- 隐私设置（`moments_visibility`：全部 / 仅好友 / 仅自己）只影响**同频圈动态**在 `post-list` 里的可见性，不影响「喜欢」「观看历史」「我的搭子」。
- 「我的搭子」里没有「删除搭子关系」的按钮（关系变更在卡片详情页里做）。
