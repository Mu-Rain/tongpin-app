## 2. 三个必须先解决的技术问题

### 2.1 167 处硬编码 hex 必须先清理（否则主题是「半身不遂」）

现在有 1046 处用了变量、167 处写死。换一套深色主题，结果是：**大部分页面变深了，但 user.vue 里 22 个地方还是浅色**，看起来像坏了。

**这是第一阶段唯一的任务，也是工作量最大的一块。** 具体：
1. 按上表顺序逐页清理（user → chat → messages → buddy → verify → detail → hall → 其余）
2. 每处硬编码判断归属哪个 token：背景类→`--tf-bg`/`--tf-card`、文字类→`--tf-text` 三级、边框类→`--tf-line`、品牌色→`--tf-primary`
3. 判断不出来的（比如某个特定标签色）先记在文档里，不要硬塞
4. **清理时不许改任何视觉效果**——先把值换成「等价变量」，跑一遍对比截图，确认像素级没变，再继续

> ⚠️ 这一步做完之前，**不要开始做主题切换**。半套变量 + 半套硬编码，主题一切换就是灾难现场。

### 2.2 动效从零开始，要定一套「动效语汇」

现在 `transition: 0` / `animation: 0`。所以不是「调整动效」，是「第一次引入动效」。

**必须定规矩，否则 31 个页面会长出 31 种动效**：

| 名 | 用途 | 时长 | 缓动 |
|---|---|---|---|
| `--tf-motion-fast` | 按钮按下、开关切换 | 120ms | ease-out |
| `--tf-motion-base` | 卡片展开/收起、列表进出 | 220ms | cubic-bezier(.4,0,.2,1) |
| `--tf-motion-slow` | 整页转场、底部弹层 | 320ms | cubic-bezier(.4,0,.2,1) |

**硬规则**：
- 只允许这三个时长，不许出现第四个
- 所有动效必须能被 `--tf-motion-scale: 0` 关掉（无障碍：有人不喜欢动）
- 列表滚动时不要加动效（小程序端会掉帧）

### 2.3 tabBar 必须改成 `custom`，否则做不了「悬浮/大小/动效」

**这是架构级决定，也是唯一有返工风险的一步。**

原生 tabBar 的能力边界：只能改颜色、高度、字号、图标宽度、间距。**不支持悬浮、不支持动效、不支持切换大小。**

用户明确要「只改变动效、大小、是否悬浮」→ 原生 tabBar 做不到 → **必须 `"custom": true`**，自己写一个 tabbar 组件。

**代价（要提前接受）**：
1. 4 个 tab 页（index / feed / messages / mine）都要引入同一个组件
2. 组件要自己处理「当前是哪个 tab」（靠页面路径判断，不用 `this.$mp` 之类的脏办法）
3. 页面底部要给 tabbar 留安全距离（悬浮态和贴底态留的高度不同 → 用 CSS 变量控制）
4. 切换 tab 用 `uni.switchTab`，不能用 `navigateTo`
5. **图标要自己准备**（原生 tabBar 用的是图片，custom 之后可以用文字/图标字体/SVG）

**建议做法**：先做一个「跟现在长得一模一样」的 custom tabBar（贴底、无动效、颜色相同），**确认 4 个页面切起来和以前一模一样**，再开始加悬浮/动效/大小变化。不要一步到位。

## 3. 架构设计：怎么做到「高可变更性」

用户把「高可变更性」标成最重要。所以核心不是「做几套主题」，而是**让「加一套主题」的成本趋近于零**。

### 3.1 四层分离

```
第 1 层 tokens      值        颜色/圆角/阴影/间距/字号/动效时长
第 2 层 variants    形态      卡片圆角or直角、按钮实心or描边、tabBar 贴底or悬浮
第 3 层 motion      动效      入场方式、按压反馈、卡片展开方式
第 4 层 pages       页面      只引用语义 class，不许写死值
```

**换主题 = 换第 1-3 层的值，第 4 层一行不动。**

### 3.2 主题定义存哪

放 `app/common/theme/presets.js`（新建），每个主题是一个纯数据对象：

```js
export default {
  default: {
    name: '默认',
    tokens: { '--tf-primary': '#FF6B4A', '--tf-radius-card': '16rpx', ... },
    variants: { card: 'round', button: 'solid', tabbar: 'docked' },
    motion: { scale: 1, cardEnter: 'fade-up' }
  },
  dark: { ... },
  // 以后加主题：在这里加一个 key
}
```

**加一套主题 = 在这个文件里加一个对象。** 这就是「高可变更性」的落地方式。

### 3.3 全局切换怎么生效

uni-app 里没有真正的「全局样式注入」，两条可行路：

**方案 A（推荐）：根节点 class 切换 + CSS 变量作用域**
- 每个页面的根 `<view class="page">` 改成 `<view class="page" :class="themeClass">`
- `themeClass` 从 `App.vue` 的全局状态取（或每个页面 `onShow` 时读本地存储）
- 主题样式写成 `.theme-dark { --tf-primary: #...; }`
- **缺点**：要改 31 个页面的根节点（机械劳动，但一次性）

**方案 B：`uni.setTabBarStyle` + 页面内注入 style**
- 只能改 tabBar 和部分全局样式，覆盖不到页面内部
- **不推荐**，能力不够

**方案 A 的替代：不改根节点，改用 `page` 选择器 + 动态设置 page 样式**
- uni-app 支持 `page { }` 选择器，但**不能在运行时切换 page 的 class**
- 所以还是得走方案 A

> **决定：用方案 A。** 31 个页面根节点加 `:class="themeClass"` 是一次性机械改动，但之后加任何主题都不用再碰页面。

### 3.4 主题页 `pages/theme/theme.vue`

- 入口：「我的」页新增一行「主题」
- 每套主题显示：预览色块 + 名字 + 一行说明
- 点击 → 立即应用（写本地存储 + 触发全局状态）→ **不用重启、不用返回重进**
- 当前主题打勾
- 底部一句：「更多主题会陆续加入」

### 3.5 主题持久化

`uni.setStorageSync('theme', 'dark')`。App 启动时 `App.vue:onLaunch` 读一次，写进全局状态（`getApp().globalData.theme` 或 `Vue.prototype.$theme`）。

每个页面 `onShow` 时从全局状态同步一次 `themeClass`，这样切完主题回到任意页面都是新的。

## 4. 用户提到的「第一次更改」怎么接

用户说「UI 现在还是现在这个（但马上会第一次更改）」——意思是：**他正在另一个会话里设计新 UI，设计完会拿过来**。

所以本次任务要做的不是「设计」，是**「搭好一个容器，让外部设计能装进来」**。

具体：**先只做「默认」这一套**，把默认主题的每个值都提取成显式的 token。等用户给新设计时：
1. 把新设计的色值/圆角/间距填进一个新主题对象
2. 新设计如果改了卡片形态（比如从圆角卡变直角卡），对应 `variants.card = 'square'`
3. 新设计如果改了动效，对应 `motion` 层

**只要 1-3 层铺好，外部设计接进来就是填表。**

## 7. 铁律（违反会出白屏或逻辑回归）

1. **只改样式，不改逻辑。** 任何 `@tap` 绑定的方法、云函数调用、数据字段一律不动。
2. `.vue` 模板里不许用 `<script>` 顶层 `const`（踩过整页白屏）。
3. 改完每个 `.vue` 必须抽 `<script>` 段跑 `node --check`（`C:\Users\lenov\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\node\bin\node.exe`）。
4. 模板引用的每个标识符必须有声明——**主题相关新增的 `themeClass` 等要挂进 `data()`**。
5. 小程序端（支付宝小程序）**不支持 `::v-deep` 之外的复杂选择器**，主题样式要扁平。
6. 动效不许影响滚动性能：列表项不加 `transition`。
7. `pages.json` 的 `tabBar` 改 `custom` 后，**4 个 tab 页的 `onShow` 逻辑不能动**。
8. 不许动 `cloudfunctions/` 下任何文件（主题纯前端）。
9. 注释只写「为什么」，全中文。
