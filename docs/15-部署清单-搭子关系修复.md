## 1. 你报的三个 bug 分别是什么原因

| # | 你看到的 | 真正的原因 |
|---|---|---|
| 1 | 成为好友后还能「邀请做搭子」 | 云函数 `user-profile` 算「能不能邀请」时**完全没看是不是好友**，只看了信誉分和有没有待处理邀请。前端按钮听它的，所以按钮一直在 |
| 2 | 点了邀请，对方直接出现搭子标签 | `buddy-invite` 在**发邀请的那一刻**就把关系写成了 `status:'active'`（已成立）。而对方主页 / 搭子列表都只查 `active` → 邀请还没被同意，关系已经生效了 |
| 3 | 聊天页有概率只显示最近一条，退出去再进又好了 | 拉消息的模块（`transport.js`）在**结果还没交给页面之前**就把「下次从这里继续」的起点推到最新一条。页面这时已经退出，30 条历史被整份丢弃，起点却停在了最新 → 再进来只拉到「比它更新」的 1 条 |

## 3. 传完之后怎么验（一台手机来回切号也行，两台更好）

### bug 1：好友不能再邀请搭子
1. A 和 B 是好友（已经是的话跳过）。
2. A 进 B 的主页 → **不应该有「邀请做搭子」按钮**，应该显示灰字「你们已经是好友了，不用再邀请搭子」。
3. 「你们之间的搭子」卡片里应该显示「你们已经是好友了，搭子关系已经收起来。」（而不是「点上面的邀请做搭子」）。

### bug 2：邀请不再提前生效
1. A 和 B **不是**好友，也**不是**搭子。
2. A 进 B 主页 → 点「邀请做搭子」→ 起名 → 发送。
3. **立刻**（不用等）让 B 打开 A 的主页 / B 的「我的搭子」页 → **不应该出现任何搭子标签**。
4. B 到「消息」页 → 顶部应该有一条搭子邀请 → 点同意 → 这时双方才出现搭子标签。
5. 反向再验一次拒绝：A 再邀请（换个类型），B 点婉拒 → 双方都不应该留下任何搭子。

### bug 3：聊天页不会再只剩一条
1. 进一个**消息很多**的会话（30 条以上），看是否完整显示历史。
2. 退到消息列表 → 再进同一个会话 → **仍然完整**。
3. 反复进出 5 次，每次都应该完整。
4. 补充验：进会话后马上按返回（在消息还没加载完时就退），再进来，**仍然完整** —— 这是原来最容易出问题的那条路径。

## 4. ★ 传完必须手动跑一次清理（重要）

你上次点「邀请做搭子」时，老代码已经在数据库里写下了一条 `status:'active'` 的**脏关系**。
只改代码不会让它消失 —— 它会继续让「你们之间的搭子」显示一个从没被同意过的标签。

我加了一个一次性的清理动作，**跑一次就好，跑第二次什么都不会改**：

1. HBuilderX → `cloudfunctions` → 右键 `buddy-invite` → **上传并运行**（注意是「上传并运行」，不是只上传）。
2. 弹出的参数框**什么都不用填**，直接确定。
3. 看控制台返回，形如：

```json
{ "code": 0, "msg": "ok", "data": { "scanned": 1, "fixed": 1, "ids": ["..."], "skipped": [] } }
```

- `scanned` = 扫到几条 active 关系
- `fixed` = 收掉了几条脏的（它的邀请从来没被同意过）
- 如果 `fixed: 0`，说明没有脏数据，不用管。
- `skipped` 里出现东西也不影响功能，把返回贴给我我再看。

> 判定规则：关系是 `active` 且来源是邀请，但那条邀请的状态**不是 accepted** → 这条关系从来没被同意过，收掉。
> **真正成立的搭子（邀请状态是 accepted）一条都不会动。**
>
> 不带参数直接运行也会走清理；带 `{ "action": "repair" }` 也一样。

## 5. 顺带修掉的两个隐患（你没报，但会导致更难查的 bug）

1. **上一轮请求没回来时退出又进入，新的一轮首次拉取会被挡掉** → 页面永远空着。
   原来的「在途请求」标志是个布尔值，退出时不清；现在改成按「第几轮」记账，新一轮一定放行。
2. **`onLoaded` 回调会被触发两次** → 页面连着做两遍「解除加载 + 刷新好友申请状态」。
   加了一次性标记，现在只触发一次。

## 6. 如果报错

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 点邀请提示「你们已经是好友了，不用再邀请搭子」 | 这是**新加的拦截**，正常行为 | 不需要处理，说明 bug 1 修好了 |
| 点邀请提示「你已经发过邀请，等他回应吧」 | 你之前发的那条还没处理 | 让对方向下翻「消息」页处理掉，或你撤回 |
| 「你们之间的搭子」还显示着旧标签 | 第 4 节的清理还没跑 | 按第 4 节跑一次 `buddy-invite` 上传并运行 |
| 聊天页还是只有一条 | 前端没更新到手机 | 停掉运行 → 重新「运行到手机」；只热更新不一定换得掉 `transport.js` |
