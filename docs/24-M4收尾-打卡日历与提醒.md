## 1. US-36 打卡日历

### 1.1 云函数：`fit-calendar`（新建）

**入参**：`{ token, month }`，`month` 形如 `2026-10`；不传默认当月。

**出参**：
```json
{ "code":0, "data": {
  "month": "2026-10",
  "today": "2026-10-24",
  "days": [ { "date":"2026-10-01", "count":2, "volume":1240.5, "sets":18, "done":true } ],
  "streak": 5,
  "month_count": 12,
  "prev_has": true, "next_has": false } }
```

- `days` **只返回有训练的日子**（前端按日期 map 到格子，不需要 30 个空对象）。
- `count` 是当天完成的训练次数（一天可能练两次）。
- `volume` / `sets` 当天合计。
- `prev_has` / `next_has`：前后一个月有没有记录，用来决定「上一月」按钮灰不灰。
- `streak` 与 `stats` 里的 `streak` **必须同一算法**（「今天还没练不算断」），不能两套。
- 只认 `status:'done'`，与 `stats` 一致（放弃的会话不算打卡）。
- `month` 格式非法 → 400。查未来月份允许，返回空 `days`。

### 1.2 前端：`pages/fitness/calendar.vue`（新建）

- 入口：`fitness.vue` 的「本月打卡」那个数字块改成可点，跳日历页。
- 月历：7 列 × 5-6 行，周一为第一列（与 `stats` 的周一起算一致）。
- 有训练的日子：底色用主色，角上一个小数字表示当天次数（1 次不显示数字）。
- 今天：加一圈描边，不是底色。
- 点某个有记录的日子 → 底部弹层显示当天的训练明细（训练名 / 组数 / 容量）。
- 顶部：`‹ 2026年10月 ›` 可切月；`prev_has=false` 时左箭头置灰。
- 顶部下方一行：`连续 N 天 · 本月 M 次`。
- 四态：加载中 / 空（整月没练，给一句鼓励）/ 出错 / 正常。

## 2. US-35 训练提醒（**降级实现**，理由见 §2.3）

### 2.1 不做的事（用户已知）

**项目从没用过 `plus` 和条件编译**，做原生本地通知需要：`#ifdef APP-PLUS` + `plus.push.createMessage` + 安卓通知权限申请 + 后台唤醒。这几样每一项都可能带来「装到别人手机上不弹」的风险，而 11/14 是功能冻结线。

**所以本轮不做系统级推送**，做**App 内到点提醒**：用户打开 App 时，如果已过提醒时间且今天还没练，首页顶部弹一条提示条。

### 2.2 做什么

**云函数：`fit-reminder`（新建）**

入参：`{ token, action: 'get' | 'set', enabled?, hour?, minute? }`

出参（get）：
```json
{ "code":0, "data": {
  "enabled": true, "hour": 20, "minute": 0,
  "should_nudge": true,
  "nudge_text": "今天还没练，要不要来一组？" } }
```

- 提醒设置存在 `uni-id-users` 上：`fit_remind_enabled` / `fit_remind_hour` / `fit_remind_minute`（三个新字段，schemaless 不需 DDL）。
- `should_nudge`：`enabled && 现在 ≥ 设定时间 && 今天没练`。三个条件都算在**服务端**，前端只负责显示。
- `hour` 0-23、`minute` 0-59，越界 400。
- 表缺失/字段缺失时按 `enabled:false` 处理，不报错。

**前端**
- `fitness.vue` 顶部：`should_nudge` 为真时显示一条提示条 +「去练一组」按钮 +「今天不再提醒」。
- 「今天不再提醒」写本地存储 `fit_nudge_silenced_date`（当天日期），当天不再调 `fit-reminder`。
- `mine.vue` 或健身页加一个「训练提醒」设置项：一个开关 + 时间选择（只用 `picker` 的 `mode="time"`）。

### 2.3 为什么降级（写清，免得以后被当缺陷）

`plus.push` 这条路需要真机调试和权限申请，且**离线通知在免费版支付宝云服务空间上不可靠**。做成 App 内提示，虽然要用户主动打开 App，但：

1. 零风险，不影响打包
2. 逻辑（时间判断、今天没练、隔天重置）全部真实且在服务端
3. M5 若还有时间，把 `should_nudge` 接到本地通知只是加一层外壳，逻辑不用重写

## 3. 铁律

1. `.vue` 模板不许用 `<script>` 顶层 const，先 `data()` 注册。
2. 云函数业务错误走 `code`；表不存在静默降级；拿不到当前用户返 500。
3. 云函数目录自包含，不许跨目录 `require`。
4. 改完 `node --check`（`C:\Users\lenov\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\node\bin\node.exe`）。
5. 注释只写「为什么」，全中文。
6. **不许动** `fit-session`（`stats` 的连续天数算法已被 `docs/09` 验收过）—— `fit-calendar` 要复用同样的算法就**复制那段逻辑**，不要改成共享函数。
7. 日历的「一周从周一开始」必须与 `fit-session:605-610` 一致，否则「本周训练」和日历对不上。

## 4. 联调验收点（跨边界，必须走真实数据）

1. **日历 ↔ 记录**：`history` 页里有 3 条记录，日历上那 3 天必须都亮；某天亮但 history 里没有那天 → 失败。
2. **日历 ↔ 连续天数**：日历页顶部「连续 N 天」必须与 `fitness` 首页那个数字**完全一致**（同一个算法）。
3. **提醒 ↔ 打卡**：设定 20:00，现在 21:00 且今天没练 → 首页出现提示条；今天练完一次再刷新 → 提示条消失。
4. **提醒 ↔ 静默**：点「今天不再提醒」后重启 App → 当天不再出现。
