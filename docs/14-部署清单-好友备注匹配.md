## 0. 一句话

**8 个云函数要上传，其中 2 个是新建（第一次传）**，其余 6 个是覆盖。前端页面跟着「运行到手机」走，不用单独部署。

## 1. 云函数清单（按上传顺序）

| # | 云函数 | 动作 | 为什么必须传 |
|---|---|---|---|
| 1 | `user-remark` | **新建** | 备注功能整个靠它，没传就写不进 `user_remarks` |
| 2 | `friend-unlink` | **新建** | 删好友靠它，没传会报 Function not found |
| 3 | `friend-request` | 覆盖 | 新增 `action:'status'` 批量查申请状态；`send` 加了三条前置判重 |
| 4 | `user-profile` | 覆盖 | 出参新增 `is_friend` / `friend_request_state` / `my_remark` 三个字段 |
| 5 | `friend-list` | 覆盖 | 出参新增 `remark` |
| 6 | `buddy-list` | 覆盖 | 出参新增 `remark` |
| 7 | `message-conversations` | 覆盖 | 出参新增 `remark` |
| 8 | `message-list` | 覆盖 | 好友申请卡片补 `fr_request_id` / `fr_status` / `fr_from_id` / `fr_to_id` |

> 第 8 个是**隐性依赖**：`chat.vue` 的 `refreshFriendRequestStates()` 要靠消息上的 `fr_request_id` 才能去查状态。不传 `message-list`，卡片状态永远停在"等待"，不会变成"已同意"。

### 怎么传

HBuilderX 左边项目管理器 → `dazi-app/app/uniCloud-alipay/cloudfunctions` → 右键单个云函数目录 → **上传部署**（不是「上传所有云函数」，那样会把 39 个一起传，慢且容易中途失败）。

新建的两个（`user-remark`、`friend-unlink`）如果右键菜单里没有「上传部署」，说明这个目录没被识别成云函数——检查目录里是否有 `index.js` 和 `package.json`（两个都在，已核对过）。

## 3. 索引（传完云函数、跑过一遍业务再建）

集合第一次被写入才会出现在控制台列表里。所以顺序是：**传云函数 → 跑一遍业务 → 回控制台建索引**。

| 集合 | 索引名 | 字段 | 唯一 |
|---|---|---|---|
| `user_remarks` | `idx_owner_target` | `owner_id` ↑, `target_user_id` ↑ | **是** |
| `friendships` | `idx_pair` | `user_a_id` ↑, `user_b_id` ↑ | **是** |
| `friendships` | `idx_user_a` | `user_a_id` ↑ | 否 |
| `friendships` | `idx_user_b` | `user_b_id` ↑ | 否 |
| `friend_requests` | `idx_to_status` | `to_user_id` ↑, `status` ↑ | 否 |
| `friend_requests` | `idx_from_status` | `from_user_id` ↑, `status` ↑ | 否 |
| `matches` | `idx_user_time` | `user_id` ↑, `created_at` ↓ | 否 |

## 4. 验收步骤（两个人，两台手机 / 或者一台手机来回切号）

```
【备注】
1. A 进 B 的主页 → 右上角三点 → 起备注「老张」→ 保存
2. A 看：标题和昵称位置都变成「老张」，下面灰色小字「用户名：<B的真实昵称>」
3. A 进好友页：B 那行显示「老张」+ 灰色小字
4. A 进消息页：B 那个会话显示「老张」
5. A 点进聊天页：顶部标题是「老张」
6. A 把备注改成空 → 保存 → 各处恢复成 B 的真实昵称，灰色小字消失

【好友申请卡片状态】
7. A 在 B 主页点「加好友」→ A 的聊天页出现卡片，标题「好友申请」，正文「已发出，等待对方同意」，底部「等待对方回应」，没有按钮
8. B 的聊天页出现同一张卡，标题「好友邀请」，正文「对方想加你为好友，同意后即可聊天」，底部「等待你回应」，有「同意」「拒绝」两个按钮
9. B 点「同意」→ **B 停留在聊天页不退出**，几秒内卡片自己变成已同意
10. A 也停留在聊天页 → 同样几秒内自己变

【删好友】
11. A 在 B 主页 → 三点 → 删除好友 → 确认
12. A 的好友页里 B 消失；A 的消息页里 B 的会话还在（历史聊天不该丢），但不再显示「好友」徽标
```

> 第 9、10 步是这轮最容易被漏掉的：对方同意**不会往会话里写新消息**，所以刷新是靠 `onLoaded`（空轮询）触发的，不是靠新消息。如果卡片不刷新，先确认 `message-list` 传了没有。

## 5. 已知限制

- 备注上限 **12 个字**（按码点算，一个 emoji 算 1 个）。前端输入框 `:maxlength` 也设成 12，但云函数仍会二次校验。
- 备注**只对起备注的人可见**。B 永远看不到 A 给他起的「老张」。
- 删好友**不会删聊天记录**，会话和消息都保留。
- 删好友**不会撤回**已经发出的好友申请历史（`friend_requests` 里的行不动）。

## 6. 如果报错

| 报错 | 原因 | 怎么办 |
|---|---|---|
| `Function not found` / `xxx 不存在` | 云函数没传上去 | 重传，等「上传成功」提示 |
| 备注保存后刷新又变回原昵称 | `user_remark` 表没建 / 唯一索引没建导致写了两条 | 先调一次 `user-remark` 让它建表，再建唯一索引 |
| 卡片状态一直「等待」 | `message-list` 没传，消息上没有 `fr_request_id` | 传 `message-list` |
| 卡片状态变了但界面不动 | 停在聊天页超过 10 秒才刷新（节流） | 正常，退出再进立刻刷新 |
| 好友页/消息页显示的是真实昵称而不是备注 | 那三个列表函数没传 | 传 `friend-list` / `buddy-list` / `message-conversations` |
