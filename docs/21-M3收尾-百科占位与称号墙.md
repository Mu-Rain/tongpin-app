## 1. 百科：`encyclopedia` 集合

字段照 `docs/03-database.md:198` 的原设计，**不加不减**：

```
_id, title(string), content(string), category(string: study/health/life/campus),
publish_date(string, 'YYYY-MM-DD'), active(bool), created_at(long)
```

索引：`publish_date` 升序 **唯一**（`docs/03:202` 明确「唯一索引只加在真正一天一条的地方」）。

> **为什么用 `publish_date` 字符串而不是时间戳**：要能按天分组和比较。见 `docs/03:200`。

## 2. 云函数：`encyclopedia-daily`（新建）

入参：`{ }`（**不需要 token** —— 首页未登录也要能看到百科）

出参：
```json
{ "code": 0, "data": {
  "item": { "title": "…", "content": "…", "category": "study", "publish_date": "2026-10-22" },
  "src": "today" } }
```
`item` 为 `null` 表示今天还没有内容（前端据此显示空态，**不是错误**）。
`src` 取值：`today`（今天这条）/ `latest`（今天没有，回落到最近一条已发布）/ `none`（一条都没有）。

**取法（顺序不可颠倒）**：
1. 先按 `{ publish_date: 今天, active: true }` 精确查。
2. 查不到 → 按 `{ active: true }` 倒序取 1 条，作为「最近一条」。
3. 都没有 → `item: null`、`src: 'none'`。
4. 表不存在（查询抛错）→ 与第 3 步一致，**不许 500**，只在日志里记一句。

「今天」按**北京时间**算（`UTC+8`）—— 服务器是 UTC，直接 `new Date().toISOString().slice(0,10)` 会在早上 8 点前算成昨天。必须显式加 8 小时再取日期。

## 3. 云函数：`encyclopedia-seed`（新建，一次性）

入参：`{ reset?: bool }`

出参：`{ code: 0, data: { inserted: n, skipped: n } }`

- 内置 **7 条**真实校园内容（不编造夸张数据，来自学习/健康/生活/校园四类）。**每条 127-155 字**——必须超过首页的折叠阈值（`ENC_FOLD_LEN = 72`），否则「展开」按钮永远不出现，那个交互等于没做。
- 按 `title` 查重，分三种处理：没有 → **插入**；有但 `content`/`category` 变了 → **原地刷新**（不动 `publish_date`，它有唯一索引）；完全一致 → 跳过。
  > 为什么要有「原地刷新」：改了内容却只能 `{reset:true}` 才生效，等于把「重传函数」这件事和白屏一样难解释。现在改了内容只需要重传函数 + 跑一次。
- 出参：`{ inserted, updated, skipped }`。
- `reset: true` 时先清空 `active: true` 的旧数据再插。
- ~~这 7 条**不带 `publish_date`**（留空串），靠回落展示~~ → **已被 §3.5 覆盖：`publish_date` 写灌入当天（北京时间）**。原理由「写死日期明天就过期」不成立，因为「过期」正是要表达的语义（→ 变「往期」），而不是要藏起来。
- 风格照抄 `tag-seed/index.js`（文件头写清「一次性、可重复调、reset 语义」）。

## 3.5 ★ 集成缺陷修正（2026-10-22，两侧都改一处）

**问题**：`encyclopedia-seed` 的 7 条内容 `publish_date` 留空串（§3 原设计），靠 `encyclopedia-daily` 的「最近一条」回落；而首页把 `src !== 'today'` 一律当「今天没更新」显示空态。**两边各自都按契约做的，合起来的结果是：灌了 seed 也永远看不到内容。**

**最终口径（本节覆盖 §2 / §3 / §5 的相关表述）**：

| `src` | 含义 | 首页表现 |
|---|---|---|
| `today` | 今天那条 | 正常显示，日期就是今天 |
| `latest` | 今天没有，回落到最近一条已发布 | **照常显示内容**，但右上角标一个「往期」+ 显示它自己的 `publish_date`。不冒充成今天 |
| `none` | 一条都没有 | 「今日百科还没更新」+「明天再看看」 |

**配套改动**：
1. `encyclopedia-seed` 插入时 `publish_date` 写**今天起往前错开 7 天**（`bjDate(i)`，i=0 是今天，i=1..6 依次昨天…前 6 天），不再是空串。
   **为什么不是「7 条全写今天」**：`publish_date` 上有**唯一索引**（§1，为「一天一条」立的），同值必然冲突 —— 全写今天只会 `inserted=1, skipped=6`，其余 6 条被 `E11000 duplicate key` 挡掉，比原缺陷更糟。错开之后 7 条全进，且第 1 条就是今天 → 当天 `src='today'`；其余 6 条成为真实往期存档，明天起 `latest` 有内容可标「往期」。
2. `encyclopedia-daily` 不变（它的回落逻辑本来就是对的）。
3. 首页 `index.vue`：`src === 'latest'` 走「显示 + 往期角标」，只有 `item` 为 null（`src === 'none'`）才走「今日还没更新」。

> 为什么不是「往期也当空态」：那样灌完 seed 的当天就看不到任何内容，答辩演示会当场尴尬；而「假装是今天的」又是骗人。标「往期」是唯一诚实的做法。

## 4. 称号墙双向视角

### 4.1 `title-list` 改造（**唯一需要改的云函数**）

入参从 `{ token }` 改为 `{ token, user_id? }`。

- `user_id` 不传或等于自己 → 现有行为完全不变（评估补发 + 拼墙 + `newly`）。
- `user_id` 是别人 → **只读**：不评估、不补发、`newly` 恒为 `[]`；`obtained` 照对方实际发过称号；`equipped` 照对方佩戴。
- `user_id` 指向不存在的用户 → **404**「找不到这位同学」（实现时补的：不校验会返回一张全「未获得」的假墙，比报错更误导）。
- token 仍然**必须**（本项目所有云函数都要求登录）。
- 出参结构一个字都不变。

**为什么要区分身份**：补发是写操作。看别人的墙却给别人补发称号，等于越权改他人数据。

### 4.2 前端

- `app/pages/title/title.vue`：`onLoad` 读 `options.user_id`；非空则进入「只看」模式——标题显示 `TA 的称号`，点卡片不弹佩戴、点已获得的也**不调 `title-equip`**（别人得自己戴）。
- `app/pages/user/user.vue`：资料卡下面加一行可点文本「TA 的称号 ›」（`applyState.is_self` 为真时不显示），跳 `/pages/title/title?user_id=<对方 id>`。
- `pages.json` **不加新路由**（复用 `pages/title/title`）。
- 「我的」页入口保持原样（不带 `user_id`）。

## 5. 首页百科卡改造

`app/pages/index/index.vue` 的占位卡（现在 57-62 行）改成：

- 有数据：标题 + 正文（正文超过 3 行折叠，点「展开」看全文）+ 分类小标 + 日期。
- 今天没有（`src !== 'today'` 或 `item` 为 null）：显示「今日百科还没更新」+ 一句「明天再看看」。
- 加载中：「正在加载今日百科…」。
- `encyclopedia-daily` 没部署 / 报错：静默降级成现在的静态占位文案，**不许白屏、不许卡住**。
- **未登录也要能看**（这个云函数不要 token）。

3. 每个云函数目录**自包含**（只有 `index.js` + `package.json`），不许 `require` 目录外的东西。
4. 表不存在时静默降级；本轮的 `encyclopedia-daily` 连 token 都不要，更不该因为表缺失报错。
