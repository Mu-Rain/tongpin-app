# 第 4 天操作清单 · 卡片详情 + 申请搭子 + 免重复登录

> 目标：把大厅里的一条卡片点开，能看完整信息、能申请；发布者能看到谁申请了，并「同意」变成搭子。
> 附带解决一个每天都会遇到的烦人事：**不用每次运行都重新登录**。
> 这一天的产物是 [05 文档 §2.1](./05-plan-and-ai-workflow.md) 里的第 4 天行。

## 二、你要点的（按顺序，别跳）

### 第 1 步 · 上传三个新云函数

在 HBuilderX 左侧 **项目管理器**里：

```
uniCloud-alipay
  └─ cloudfunctions
       ├─ card-detail      ← 右键 → 【上传部署】
       ├─ card-apply       ← 右键 → 【上传部署】
       └─ user-auto-login  ← 右键 → 【上传部署】
```

> ⚠️ **别点「运行-云函数测试」**。那个会去找 `*.test.js` 测试文件，我们没写，必然失败——第 2 天你已经踩过一次了。

### 第 1.5 步 · 验收免重复登录（这个不用等第 3 步，先试它）

1. 真机运行一次，**正常登录**
2. 在 HBuilderX 里**停止运行**，再**重新运行**一次
3. 这次进到登录页时，顶部应该出现一块橙色浅底的卡片：
   > **检测到已登录：你的昵称**
   > 你的学校 · 信誉 100
   > 　【换个账号登录】　【直接进首页 →】

   —— 出现它就说明 `user-auto-login` 通了。**点【直接进首页】**就进去了，不用再输密码。

> **为什么不做成"全自动跳首页"**：你自己选的这个方案。好处是测试第二个账号时不用先手动退出——
> 直接点【换个账号登录】就行。坏处是多一次点击，但换来的是切号方便。

### 第 2 步 · 重新运行到手机

因为改了 `pages.json`（新页面要注册），**必须重新编译运行，热重载不一定认**：

- 菜单【运行】→【运行到手机或模拟器】→ 选你的设备
- 如果页面没变化：先【运行】→【停止运行】，再重新运行一次

### 第 3 步 · 验收：申请人视角（你现在的账号如果没发过卡片）

1. 首页 → 点【搭子大厅】→ 随便点一张**别人发的**卡片
2. 应该看到：发布者头像/昵称/学校/信誉分 → 卡片标题正文 → 标签 → 「你们有 N 个共同标签」→ 时间地点 → 发布于 X
3. 底部有一个橙色按钮 **【我想搭 · 申请】**
4. 点它 → 弹出输入框 → 打一句话 → 点【发送申请】
5. 提示「申请已发送」，按钮变成灰字 **「申请已提交，等待对方回应」** + 出现【撤回申请】按钮

### 第 4 步 · 验收：发布者视角（需要一个第二个账号，或你自己发的卡）

> 没有第二个手机？**在电脑浏览器/第二台设备上注册第二个账号**最快。
> 或者：用同一个账号看不到自己的申请（代码里挡住了「不能申请自己的卡片」），所以要两个账号才能走完闭环。

1. 用 **A 账号**发一张卡片
2. 用 **B 账号**去大厅找到它，申请
3. 回到 **A 账号**，重新进这张卡片的详情页
4. 应该看到多了一块 **【收到的申请（1）】**，里面有 B 的昵称、学校、信誉分、留言
5. 点 **【同意，成为搭子】** → 提示「配对成功，去消息里聊聊」
6. 这时候后台其实已经干了 4 件事（见下面第三节），只是聊天页第 5 天才做，所以点「去聊聊」暂时只弹提示

## 三、点「同意」的时候，后台发生了什么

这是第 4 天最值钱的一段逻辑。**一次点击改了 4 张集合**：

| 顺序 | 改什么 | 为什么 |
|---|---|---|
| 1 | `applications` 这条 → `accepted` | 记录结果 |
| 2 | `cards` 这张卡 → `matched` | 卡片不能再被申请 |
| 3 | 其它 `pending` 申请 → `rejected`，各发一条通知 | **一张卡只成一个搭子**，不然一堆人抢 |
| 4 | 新建 `buddy_relations`（双向一条，`user_a_id < user_b_id`） | 从此两人是搭子 |
| 5 | 新建 `conversations(type='direct')` + 两条 `conversation_members` | 才有地方聊天（第 5 天用） |

> 严格来说这 5 步应该包在一个**事务**里。当前实现是顺序执行 + 每一步都有校验；
> 单机演示够用，但如果后面并发上来了，要把它们改成 `db.startTransaction()`。这一条记在案。

## 四、怎么在后台确认数据真的写对了

HBuilderX 里打开 **uniCloud 控制台**（左侧 `uniCloud-alipay` 右键 → 【打开 uniCloud web 控制台】）→ 【云数据库】：

| 点完【申请】后，去这个集合看 | 应该有 |
|---|---|
| `applications` | 一条新记录，`status: 'pending'`，`message` 是你写的留言 |
| `notifications` | 一条给发布者的通知 |

| 点完【同意】后，去这个集合看 | 应该有 |
|---|---|
| `applications` | 那条变 `accepted`，同卡其它 pending 变 `rejected` |
| `cards` | 那张卡 `status: 'matched'` |
| `buddy_relations` | 一条新记录，`label_a`/`label_b` 都是空串 |
| `conversations` | 一条 `type: 'direct'`，`buddy_relation_id` 指向上面那条 |
| `conversation_members` | 两条，两个 user_id 各一条 |

> 如果某个集合「不存在」——那是正常的。**uniCloud 是文档型数据库，第一次写入时才自动建集合。**
> 这也是为什么第 2 天 `tag-seed` 要手动跑一次来灌标签数据。

## 五、报错对照表

| 屏幕上看到的 | 真实原因 | 怎么办 |
|---|---|---|
| 页面白屏 / 点卡片没反应 | 新页面没注册 | 确认 `pages.json` 里有 `pages/detail/detail`，然后**重新运行**（不是热重载） |
| 「云函数 card-detail 调用失败，检查是否已部署」 | 云函数没上传 | 回第 1 步，右键 →【上传部署】 |
| 「登录已过期，请重新登录」 | token 不存在或对不上 | 退出登录重新登一次；如果还不行，看是不是又用了 `users` 而不是 `uni-id-users` |
| 「不能申请自己的卡片」 | 你点的是自己发的卡 | 正常，用另一个账号 |
| 「这张卡片已经找到搭子了」 | 卡片 status 已经是 matched | 正常，一张卡只成一个搭子 |
| 「你已经申请过了，等对方回应吧」 | 重复申请 | 正常，防重复的逻辑生效了 |
| 「你的信誉分低于 60，暂时不能申请搭子」 | 信誉分规则生效 | 正常 |
| 「打不开这张卡片」+ 返回大厅 | 卡片 id 不存在 / 卡片被下架（`removed`） | 从大厅重新点进去；下架的卡只有发布者本人能看 |
| 「你们有 0 个共同标签」没显示 | 正常 | 这一块只在 `common_tag_count > 0` 时才出现 |
| 【收到的申请】块没出现 | 只有**发布者本人**能看到 | 确认你登录的是发卡片那个账号 |
| 重新运行后**没有**「检测到已登录」卡片 | `App.vue` 还没编译进去，或 `user-auto-login` 没上传 | 确认已【上传部署】；再确认 HBuilderX 里 `App.vue` 有 `tryAutoLogin`；最后彻底停止运行再重来 |
| 「检测到已登录」卡片有时要等一两秒才出现 | 正常 | 云函数是异步的，页面开了 300ms 会补读一次本地缓存 |
| 退出登录后回到登录页，还显示「检测到已登录」 | 退出时没清 `autoLogin`（已修） | 确认 `index.vue` 的 `onLogout` 里有 `removeStorageSync('autoLogin')` |
| 自动登录后进首页，昵称/信誉没更新 | 正常 | 自动登录会顺手刷新 `userInfo`，但首页是 `onShow` 读本地，来回切一次页面就新了 |

## 七、明天（第 5 天）要做什么

**聊天**。这是 M2 主链闭环的最后一环，也是答辩最重要的演示：

| 要做 | 说明 |
|---|---|
| 云函数 `chat-send` / `chat-fetch` / `chat-list` | 发消息 / 拉新消息 / 拉会话列表 |
| 页面 `pages/messages/messages` | 消息列表（会话 + 未读数） |
| 页面 `pages/chat/chat` | 聊天页，**3 秒轮询**，按 [06-chat-transport.md](./06-chat-transport.md) 的 7 个接口写 |
| 「去聊聊」按钮 | 现在弹的是占位提示，第 5 天要换成真跳转 |

> 传输层**必须走 `common/chat/transport.js` 的接口**，不要在页面里直接写 `setInterval`。
> 原因是：你要求的「以后能换 WebSocket」这个口子，就靠这层隔离。页面只认接口，不认实现。
